## 1. Problem Statement

> Given an integer array `nums` and an integer `k`, return `true` if there are two **distinct indices** `i` and `j` in the array such that `nums[i] == nums[j]` and `abs(i - j) <= k`.

**Example 1:**  
Input: `nums = [1,2,3,1]`, `k = 3`  
Output: `true`  
Explanation: `nums[0] == nums[3]` and `abs(0 - 3) = 3 <= k`.

**Example 2:**  
Input: `nums = [1,0,1,1]`, `k = 1`  
Output: `true`  
Explanation: `nums[2] == nums[3]` and `abs(2 - 3) = 1 <= k`.

**Example 3:**  
Input: `nums = [1,2,3,1,2,3]`, `k = 2`  
Output: `false`  
Explanation: No two distinct indices `i` and `j` satisfy the condition.

## 2. Constraints & Key Observations

- **Constraints:**
    - `1 <= nums.length <= 10^5`
    - `-10^9 <= nums[i] <= 10^9`
    - `0 <= k <= 10^5`

- **What constraints tell us:**
    - `nums.length` up to `10^5` implies we need an **O(n)** solution; **O(n²)** is too slow.
    - `k` can be `0`, which means **no duplicates are allowed** (but `k=0` is a valid input).

- **Key observations:**
    - We only need to track the **most recent index** of each number to check for duplicates within `k` distance.
    - If a duplicate is found **beyond** `k` distance, we **update** the stored index to the **newer** one (since future duplicates are more likely to be within `k`).

- **Edge cases to handle:**
    - `k = 0`: No valid duplicates allowed.
    - All elements are unique.
    - Duplicates are exactly `k` apart.
    - Duplicates are more than `k` apart but later duplicates are within `k`.

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** We can use a **hash map** to store the **last seen index** of each number. This allows us to check for duplicates in **constant time**.
- **Algorithm invariant:** At any point, the hash map contains the **most recent index** of each number seen so far.
- **Why this works:** By only storing the latest index, we ensure that we are always checking the **closest possible** previous occurrence of a duplicate. If the distance is too large, we **update** the map to the new index, which may help future comparisons.

### 3.2 Algorithm Strategy

1. Initialize an empty hash map to store the **last seen index** of each number.
2. Iterate through the array with an index `i`:
    - If the current number is in the map and the distance from the stored index is `<= k`, return `true`.
    - If the current number is not in the map, or the distance is `> k`, update the map with the **current index**.
3. If the loop completes without finding a valid duplicate, return `false`.

## 4. Example Walkthrough

**Input:** `nums = [1,0,1,1]`, `k = 1`

**Initial state:**
- `dict` is empty.

**Execution trace:**

- **Step 1 (i=0, nums[i]=1):**  
  `dict` does not contain `1` → add `1:0`.

- **Step 2 (i=1, nums[i]=0):**  
  `dict` does not contain `0` → add `0:1`.

- **Step 3 (i=2, nums[i]=1):**  
  `dict` contains `1` with index `0`.  
  `i - dict[1] = 2 - 0 = 2 > 1` → update `dict[1] = 2`.

- **Step 4 (i=3, nums[i]=1):**  
  `dict` contains `1` with index `2`.  
  `i - dict[1] = 3 - 2 = 1 <= 1` → return `true`.

## 5. Complexity Analysis

- **Time Complexity:** `O(n)` — We iterate through the array once.
- **Space Complexity:** `O(n)` — The hash map stores up to `n` entries (one for each unique number).

## 6. Code Solution

```cpp
#include <unordered_map>
using namespace std;

class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        unordered_map<int, int> dict;
        for (int i = 0; i < nums.size(); ++i) {
            if (dict.find(nums[i]) != dict.end() && i - dict[nums[i]] <= k) {
                return true;
            }
            dict[nums[i]] = i;  // Always update to the latest index
        }
        return false;
    }
};
```

## 7. Pattern Recognition

- **Pattern Name:** Hash Table - Tracking Last Seen Indices
- **Reusable Framework:**
    ```cpp
    unordered_map<T, int> map;
    for (int i = 0; i < n; ++i) {
        if (map.find(current) != map.end() && i - map[current] <= k) {
            return true;
        }
        map[current] = i;
    }
    return false;
    ```
- **When to use this pattern:**
    - When you need to find **duplicates within a certain range**.
    - When you want to **track the most recent occurrence** of an element for efficient lookup.

## 8. Key Insights

- **Main Insight:** Use a hash map to store the **latest index** of each number. This allows **O(1)** lookup and ensures we only compare with the **closest possible** previous occurrence.
- **Common Mistake:** Storing **all** previous indices (e.g., using a list) instead of just the latest one. This increases space complexity and is unnecessary.
