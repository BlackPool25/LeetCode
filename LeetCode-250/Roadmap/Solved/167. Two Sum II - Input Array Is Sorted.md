

# 167. Two Sum II - Input Array Is Sorted

## 1. Problem Statement

> **Given a 1‑indexed array of integers `numbers` that is already sorted in non‑decreasing order, find two numbers such that they add up to a specific `target` number. Let these two numbers be `numbers[index1]` and `numbers[index2]` where `1 <= index1 < index2 <= numbers.length`. Return the indices of the two numbers, `index1` and `index2`, added by one as an integer array `[index1, index2]` of length 2.**  
> The tests are generated such that there is **exactly one solution**. You **may not** use the same element twice.  
> Your solution must use only constant extra space.  

**Example 1:**

**Input:** `numbers = [2,7,11,15]`, `target = 9`  
**Output:** `[1,2]`  
**Explanation:** The sum of 2 and 7 is 9. Therefore, `index1 = 1`, `index2 = 2`. We return `[1, 2]`.

**Example 2:**

**Input:** `numbers = [2,3,4]`, `target = 6`  
**Output:** `[1,3]`  
**Explanation:** The sum of 2 and 4 is 6. Therefore, `index1 = 1`, `index2 = 3`. We return `[1, 3]`.

**Example 3:**

**Input:** `numbers = [-1,0]`, `target = -1`  
**Output:** `[1,2]`  
**Explanation:** The sum of -1 and 0 is -1. Therefore, `index1 = 1`, `index2 = 2`. We return `[1, 2]`.

**Constraints:**

- `2 <= numbers.length <= 3 * 10^4`  
- `-1000 <= numbers[i] <= 1000`  
- `numbers` is sorted in **non‑decreasing order**.  
- `-1000 <= target <= 1000`  
- The tests are generated such that there is **exactly one solution**.

## 2. Constraints & Key Observations

- **Constraints:**
  - Array length is at least 2 and at most 30,000.
  - Values range from -1000 to 1000.
  - Array is sorted in non‑decreasing order.
  - Exactly one pair sums to the target.

- **What constraints tell us:**
  - `n ≤ 3·10^4` → an \(O(n^2)\) solution would be too slow; we need \(O(n)\) or \(O(n \log n)\).
  - Sorted array allows us to use two‑pointer technique in linear time.
  - Constant extra space requirement rules out hash‑map solutions.

- **Key observations:**
  - Because the array is sorted, increasing the left pointer (`front`) increases the sum, while decreasing the right pointer (`rear`) decreases the sum.
  - The unique solution guarantees that once we find the correct pair we can return immediately.

- **Edge cases to handle:**
  - Negative numbers (e.g., `[-1, 0]`).
  - Duplicate values (e.g., `[1, 1, 2, 2]`).
  - Target that is the sum of the smallest and largest elements.
  - Target that is the sum of two middle elements.

## 3. Solution Development

### 3.1 Core Intuition

- **Aha!** Use two pointers starting at opposite ends of the sorted array.  
- **Invariant:** At any time, the pair `(front, rear)` encloses all potential solutions; moving one pointer narrows the search space while preserving the invariant.  
- **Why it works:** Because the array is sorted, we can decide which pointer to move based solely on the comparison of the current sum with the target.

### 3.2 Algorithm Strategy

1. Initialize `front` to the first index (`0`) and `rear` to the last index (`numbers.size() - 1`).  
2. While `front < rear`:
   - Compute `sum = numbers[front] + numbers[rear]`.
   - If `sum == target`, return `[front+1, rear+1]` (1‑indexed).  
   - If `sum > target`, decrement `rear` to reduce the sum.  
   - If `sum < target`, increment `front` to increase the sum.  
3. If the loop ends without finding a pair (theoretically impossible due to problem guarantees), return an empty vector.

3. **Step 3:**

   - `sum == target` → return `[front+1, rear+1] = [1, 2]`

Input: `numbers = [-1,0]`, `target = -1`

- `sum = -1 + 0 = -1` → equals target → return `[1, 2]`.

## 5. Complexity Analysis

- **Time Complexity:** \(O(n)\)  
  - The `while` loop moves each pointer at most once, resulting in at most \(n-1\) iterations.  
- **Space Complexity:** \(O(1)\)  
  - Only a few integer variables (`front`, `rear`, `sum`) are used; no additional data structures grow with input size.

## 6. Code Solution (C++)

```cpp
class Solution {

public:

vector<int> twoSum(vector<int>& numbers, int target) {

int front = 0;

int rear = numbers.size()-1;

  

while(front<rear){

int sum = numbers[front] + numbers[rear];

  

if(sum == target){

return {front+1, rear+1};

}

else if(sum > target){

rear--;

}

else{

front++;

}

}

  

return {};

}

};

```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**
  - The input array is sorted.
  - You need to find a pair (or subarray) that satisfies a numeric condition.
  - You can compare the current sum (or product) with the target to decide which pointer to move.
  - The solution must use constant extra space.

- **Pattern Structure (reusable template):**

```cpp
// Two Pointers – Opposite Ends
int left = 0;                     // start of array
int right = arr.size() - 1;       // end of array

while (left < right) {
    int current = arr[left] + arr[right]; // or other comparison

    if (current == target) {
        // found solution
        return {left + 1, right + 1};     // adjust for 1‑indexing if needed
    } else if (current > target) {
        right--;                          // move right pointer leftwards
    } else {
        left++;                           // move left pointer rightwards
    }
}
```

### 🔑 Core Insights

- **Sortedness is the lever:** It lets us make a deterministic decision about pointer movement.
- **Invariant maintenance:** Each pointer movement keeps the search window valid.
- **Early exit:** Unique solution guarantee allows immediate return.
