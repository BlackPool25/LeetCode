

# 344. Reverse String

## 1. Problem Statement

> Write a function that reverses a string. The input string is given as an array of characters `s`.  
>  
> You must do this by modifying the input array **in-place** with `O(1)` extra memory.  
>  
> **Example 1:**  
> Input: `s = ["h","e","l","l","o"]`  
> Output: `["o","l","l","e","h"]`  
> Explanation: The array is reversed in-place with no additional memory used.  
>  
> **Example 2:**  
> Input: `s = ["H","a","n","n","a","h"]`  
> Output: `["h","a","n","n","a","H"]`  

---

## 2. Constraints & Key Observations

- **Constraints:**
    - `1 <= s.length <= 10^5`
    - `s[i]` is a printable ASCII character.

- **What constraints tell us:**
    - `s.length` can be up to 100,000, so any $O(n^2)$ algorithm is infeasible.
    - `O(1)` memory requirement rules out using extra arrays or recursion.

- **Key observations:**
    - The problem requires **in-place reversal**, which strongly suggests a **two-pointer approach**.
    - Swapping characters from both ends toward the center is the most efficient way to achieve this.

- **Edge cases to handle (based on actual constraints):**
    - Single-element array (e.g., `["a"]` → no swap needed).
    - Even-length array (e.g., `["a", "b"]` → one swap).
    - Odd-length array (e.g., `["a", "b", "c"]` → two swaps, middle element remains).

---

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:**  
  Reversing an array in-place can be done by swapping elements from both ends toward the center. This ensures no extra memory is used.

- **Algorithm invariant:**  
  At any point in the algorithm, the characters at positions `front` and `rear` are swapped, and the pointers move inward until they meet.

- **Why this works:**  
  Each character is swapped exactly once, and the process guarantees that the array is reversed in-place with minimal operations.

---

### 3.2 Algorithm Strategy

1. Initialize two pointers: `front` at the start of the array and `rear` at the end.
2. While `front <= rear`, swap the characters at these positions.
3. Move `front` forward and `rear` backward after each swap.
4. Terminate when `front` exceeds `rear`.

---

## 4. Example Walkthrough

**Input:** `s = ["h","e","l","l","o"]`

**Initial state:**
- `front = 0`, `rear = 4`
- `s = ["h", "e", "l", "l", "o"]`

**Execution trace:**

- **Step 1:** Swap `s[0]` and `s[4]` → `["o", "e", "l", "l", "h"]`, `front = 1`, `rear = 3`
- **Step 2:** Swap `s[1]` and `s[3]` → `["o", "l", "l", "e", "h"]`, `front = 2`, `rear = 2`
- **Step 3:** `front <= rear` is true, but `front == rear` → no swap needed.
- **Step 4:** `front` increments to 3, `rear` decrements to 1 → loop ends.

**Final result:** `["o", "l", "l", "e", "h"]`

---

## 5. Complexity Analysis

- **Time Complexity:** $O(n)$  
  - **Why:** Each character is swapped exactly once, and the loop runs $n/2$ times.

- **Space Complexity:** $O(1)$  
  - **Why:** Only a few variables (`front`, `rear`, `temp`) are used, independent of input size.

---

## 6. Code Solution (C++)

```cpp
class Solution {
public:
    void reverseString(vector<char>& s) {
        if(s.size() == 0) return;
        int front = 0;
        int rear = s.size()-1;
        while(front <= rear){
            char temp = s[rear];
            s[rear] = s[front];
            s[front] = temp;
            front++;
            rear--;
        }
    }
};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**
    - The input is an array and needs to be modified **in-place**.
    - The goal is to reverse or transform elements symmetrically.
    - Memory constraints are strict (e.g., `O(1)` space).

- **Pattern Structure (reusable template):**

```cpp
// Two Pointers - Opposite Ends
// Swap elements from both ends toward the center

int front = 0;  // Start of array
int rear = s.size() - 1;  // End of array

while (front <= rear) {
    // Swap elements at front and rear
    char temp = s[rear];
    s[rear] = s[front];
    s[front] = temp;

    // Move inward
    front++;
    rear--;
}
```

---

### 💡 Key Insights

- **Core technique:** Use two pointers to swap elements from both ends toward the center.
- **Optimization:** Avoid unnecessary swaps by checking `front <= rear` before swapping.
- **Common mistake:** Forgetting to increment/decrement both pointers after a swap, leading to infinite loops.
