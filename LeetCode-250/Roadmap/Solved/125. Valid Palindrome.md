

# 125. Valid Palindrome

## 0. Problem Metadata

- **Difficulty:** Easy
- **Topics/Tags:** Two Pointers, String, Character
- **Pattern Category:** Two Pointers – Same Direction (Fast‑Slow) with Skipping Non‑Alphanumeric
- **LeetCode Link:** https://leetcode.com/problems/valid-palindrome/

## 1. Problem Statement

> **A phrase is a palindrome if, after converting all uppercase letters into lowercase letters and removing all non‑alphanumeric characters, it reads the same forward and backward. Alphanumeric characters include letters and numbers.**  
> 
> Given a string `s`, return `true` if it is a palindrome, or `false` otherwise.
> 
> **Example 1:**  
> **Input:** `s = "A man, a plan, a canal: Panama"`  
> **Output:** `true`  
> **Explanation:** `"amanaplanacanalpanama"` is a palindrome.
> 
> **Example 2:**  
> **Input:** `s = "race a car"`  
> **Output:** `false`  
> **Explanation:** `"raceacar"` is not a palindrome.
> 
> **Example 3:**  
> **Input:** `s = " "`  
> **Output:** `true`  
> **Explanation:** `s` is an empty string `""` after removing non‑alphanumeric characters. An empty string reads the same forward and backward, so it is a palindrome.
> 
> **Constraints:**  
> - `1 <= s.length <= 2 * 10^5`  
> - `s` consists only of printable ASCII characters.

## 2. Constraints & Key Observations

- **Constraints:**
  - `1 ≤ s.length ≤ 200,000`
  - `s` contains only printable ASCII characters.
- **What constraints tell us:**
  - The input can be very long, so an \(O(n^2)\) algorithm is infeasible.  
  - We must process each character at most a constant number of times → aim for \(O(n)\) time.
  - The string is never empty, but after filtering non‑alphanumeric characters it can become empty.
- **Key observations:**
  - Palindrome property is symmetric: the first and last relevant characters must match, then the second and second‑last, etc.
  - Non‑alphanumeric characters can be ignored; they do not affect the palindrome check.
  - Case is irrelevant; all letters should be compared in the same case (lowercase).
- **Edge cases to handle:**
  - Single character strings (always a palindrome).
  - Strings that contain only non‑alphanumeric characters (becomes empty → palindrome).
  - Strings where the first or last character is non‑alphanumeric and must be skipped.
  - Mixed case letters that should be compared case‑insensitively.

## 3. Solution Development

### 3.1 Core Intuition

- **Aha!** We can compare characters from both ends, skipping any that are not alphanumeric, and normalizing case on the fly.  
- **Invariant:** At any point, `begin` points to the next alphanumeric character from the left, and `end` points to the next alphanumeric character from the right.  
- **Why it works:** If all such mirrored pairs match, the cleaned string is a palindrome; otherwise, it is not.

### 3.2 Algorithm Strategy

1. Initialize two indices, `begin` at the start and `end` at the end of the string.  
2. While `begin <= end`:
   - Skip non‑alphanumeric characters at `begin` by incrementing `begin`.  
   - Skip non‑alphanumeric characters at `end` by decrementing `end`.  
   - Compare the lowercase forms of `s[begin]` and `s[end]`.  
   - If they differ, return `false`.  
   - Otherwise, move both pointers inward (`begin++`, `end--`).  
3. If the loop completes without mismatches, return `true`.

## 5. Complexity Analysis

- **Time Complexity:** \(O(n)\)  
  - Each character is examined at most twice (once by each pointer).  
  - All operations inside the loop are constant time.
- **Space Complexity:** \(O(1)\)  
  - Only a few integer indices and no additional data structures are used.

## 6. Code Solution (C++)

```cpp
class Solution { public: bool isPalindrome(string s) { 
    int begin = 0; 
    int end = s.length() - 1; 
    while(begin <= end){
        if(!isalnum(s[begin])){ 
            begin++; 
            continue; 
        } 
        if(!isalnum(s[end])){ 
            end--; 
            continue; 
        } 
        if(tolower(s[begin]) != tolower(s[end])) return false; 
        begin++; 
        end--; 
    } 
    return true; 
} };
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**
  - The input is a string that may contain irrelevant characters (e.g., punctuation, spaces).  
  - You need to compare characters symmetrically from both ends.  
  - The comparison must be case‑insensitive or otherwise normalized.  
  - You can skip over non‑relevant characters without storing a cleaned version.
- **Pattern Structure (reusable template):**

```cpp
// Two Pointers – Same Direction (Fast‑Slow) with Skipping
int left = 0;          // tracks next relevant character from the left
int right = s.size()-1; // tracks next relevant character from the right

while (left <= right) {
    if (!isRelevant(s[left])) { left++; continue; }   // skip left
    if (!isRelevant(s[right])) { right--; continue; } // skip right

    if (normalize(s[left]) != normalize(s[right])) return false;

    left++; right--;   // move inward after a successful match
}
return true;          // all mirrored pairs matched
```

### 📌 Why the Two‑Pointer Skipping Approach Is Efficient

- **No extra memory:** You avoid allocating a new string for the cleaned input.  
- **Linear scan:** Each pointer moves monotonically toward the center, guaranteeing \(O(n)\) time.  
- **Early exit:** As soon as a mismatch is found, the algorithm stops, which can be faster on average.
