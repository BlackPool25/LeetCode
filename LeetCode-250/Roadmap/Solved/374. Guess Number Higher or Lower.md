

# 374. Guess Number Higher or Lower

## 1. Problem Statement

> We are playing the Guess Game. The game is as follows:  
> I pick a number from `1` to `n`. You have to guess which number I picked (the number I picked stays the same throughout the game).  
> Every time you guess wrong, I will tell you whether the number I picked is higher or lower than your guess.  
> You call a pre-defined API `int guess(int num)`, which returns three possible results:  
> - `-1`: Your guess is higher than the number I picked (i.e., `num > pick`).  
> - `1`: Your guess is lower than the number I picked (i.e., `num < pick`).  
> - `0`: Your guess is equal to the number I picked (i.e., `num == pick`).  
> Return the number that I picked.  

**Example 1:**  
Input: `n = 10, pick = 6`  
Output: `6`  
Explanation: The number picked is 6, and the algorithm correctly identifies it through binary search.  

**Example 2:**  
Input: `n = 1, pick = 1`  
Output: `1`  

**Example 3:**  
Input: `n = 2, pick = 1`  
Output: `1`  

---

## 2. Constraints & Key Observations

- **Constraints:**  
    - `1 <= n <= 2^31 - 1`  
    - `1 <= pick <= n`  

- **What constraints tell us:**  
    - `n` can be as large as `2^31 - 1`, so any linear search (O(n)) is infeasible.  
    - Binary search (O(log n)) is the only viable approach.  

- **Key observations:**  
    - The numbers are in a **sorted range** (1 to n), and the API gives **direct feedback** on whether the guess is higher or lower.  
    - This is a **classic binary search** scenario where each guess reduces the search space by half.  

- **Edge cases to handle (based on actual constraints):**  
    - `n = 1` (only one possible number)  
    - `pick = 1` or `pick = n` (edge of the search range)  

---

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** The problem is a **direct application of binary search** on a sorted range.  
- **Algorithm invariant:** At every step, the number is guaranteed to be within the current `[front, rear]` range.  
- **Why this works:** Binary search minimizes the number of guesses by halving the search space at each step, ensuring logarithmic time complexity.  

### 3.2 Algorithm Strategy

1. Initialize two pointers: `front = 1` (start of range), `rear = n` (end of range).  
2. While `front <= rear`:  
    - Compute `mid = front + (rear - front) / 2` (to avoid integer overflow).  
    - Use the `guess(mid)` API to determine if the target is higher, lower, or equal to `mid`.  
    - If `guess(mid) == 0`, return `mid` as the correct number.  
    - If `guess(mid) == -1`, the target is **lower** than `mid`, so update `rear = mid - 1`.  
    - If `guess(mid) == 1`, the target is **higher** than `mid`, so update `front = mid + 1`.  
3. If the loop ends without finding the number (impossible due to constraints), return `-1` (a fallback).

## 4. Example Walkthrough

**Input:** `n = 10, pick = 6`  

**Initial state:**  
- `front = 1`, `rear = 10`  

**Execution trace:**  
- **Step 1:** `mid = 5.5 → 5` (integer division), `guess(5)` returns `1` (target is higher).  
    - Update `front = 6`.  
- **Step 2:** `mid = (6 + 10) / 2 = 8`, `guess(8)` returns `-1` (target is lower).  
    - Update `rear = 7`.  
- **Step 3:** `mid = (6 + 7) / 2 = 6.5 → 6`, `guess(6)` returns `0` (correct).  
    - Return `6`.  

**Final result:** `6`

## 5. Complexity Analysis

- **Time Complexity:** $O(\log n)$  
    - Why: Each iteration reduces the search space by half, requiring at most $\log_2 n$ steps.  

- **Space Complexity:** $O(1)$  
    - Why: Only constant variables (`front`, `rear`, `mid`, `res`) are used, independent of input size.  

---

## 6. Code Solution (C++)

```cpp
class Solution {
public:
    int guessNumber(int n) {
        int front = 1;
        int rear = n;
        while (front <= rear) {
            int mid = front + (rear - front) / 2;
            int res = guess(mid);
            if (res == 0) return mid;
            else if (res == -1) rear = mid - 1;
            else front = mid + 1;
        }
        return -1;
    }
};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**  
    - The input is a **sorted range** (e.g., 1 to n)  
    - You need to **find a specific value** using **comparisons** (higher/lower)  
    - **Binary search** is the optimal approach due to logarithmic time complexity  

- **Pattern Structure (reusable template):**  
```cpp
// Binary Search - Classic
// Search for a target in a sorted range [1, n]

int front = 1;  // Start of search range
int rear = n;  // End of search range

while (front <= rear) {
    int mid = front + (rear - front) / 2;  // Avoid overflow
    int res = guess(mid);  // API call to compare
    if (res == 0) return mid;  // Found the target
    else if (res == -1) rear = mid - 1;  // Target is lower
    else front = mid + 1;  // Target is higher
}
return -1;  // Fallback (should not be reached)
```

---

### 📌 Common Pitfalls

- **Off-by-one errors** in the `front` and `rear` updates.  
- **Integer overflow** when computing `mid` (use `front + (rear - front) / 2` instead of `(front + rear) / 2`).
