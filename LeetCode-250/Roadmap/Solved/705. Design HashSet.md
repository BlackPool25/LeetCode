## 1. Problem Statement

> **Design a HashSet without using any built-in hash table libraries.**  
>  
> Implement `MyHashSet` class:  
>  
> - `void add(key)` Inserts the value `key` into the HashSet.  
> - `bool contains(key)` Returns whether the value `key` exists in the HashSet or not.  
> - `void remove(key)` Removes the value `key` in the HashSet. If `key` does not exist in the HashSet, do nothing.  
>  
> **Example 1:**  
> Input:  
> ["MyHashSet", "add", "add", "contains", "contains", "add", "contains", "remove", "contains"]  
> Output:  
> [null, null, null, true, false, null, true, null, false]  
>  
> **Explanation**  
> MyHashSet myHashSet = new MyHashSet();  
> myHashSet.add(1);      // set = [1]  
> myHashSet.add(2);      // set = [1, 2]  
> myHashSet.contains(1); // return True  
> myHashSet.contains(3); // return False, (not found)  
> myHashSet.add(2);      // set = [1, 2]  
> myHashSet.contains(2); // return True  
> myHashSet.remove(2);   // set = [1]  
> myHashSet.contains(2); // return False, (already removed)

## 2. Constraints & Key Observations

- **Constraints:**  
    - `0 <= key <= 10^6`  
    - At most `10^4` calls will be made to `add`, `remove`, and `contains`.  

- **What constraints tell us:**  
    - `key` can be up to `10^6`, but only `10^4` operations are expected → a simple hash table with chaining is sufficient.  
    - No need for advanced optimizations like dynamic resizing or open addressing.  

- **Key observations:**  
    - A basic hash table with chaining (linked lists) can be used to handle collisions.  
    - The number of buckets (`numBuckets`) is chosen as a prime number (769) to reduce collisions.  
    - The `contains` method must be efficient to avoid redundant operations.  

- **Edge cases to handle (based on actual constraints):**  
    - `key = 0` (must be handled correctly)  
    - Duplicate keys (must be ignored in `add`)  
    - Removing a key that does not exist (must do nothing)

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:**  
  Use a hash table with chaining (linked lists) to resolve collisions. Each bucket is a linked list of keys that hash to the same index.  

- **Algorithm invariant:**  
  At any point, the linked list in each bucket contains all keys that hash to that bucket.  

- **Why this works:**  
  By using a hash function and chaining, we can efficiently insert, remove, and check for the presence of keys in average $O(1)$ time.  

---

### 3.2 Algorithm Strategy

1. **Initialize a fixed-size array of buckets** (linked lists) using a prime number (769) to minimize collisions.  
2. **Hash the key** using modulo to determine the bucket index.  
3. **For `add`:**  
   - If the key already exists in the bucket, do nothing.  
   - Otherwise, insert the key at the head of the linked list for that bucket.  
4. **For `remove`:**  
   - Traverse the linked list in the bucket to find the key.  
   - If found, remove the node from the linked list.  
5. **For `contains`:**  
   - Traverse the linked list in the bucket to check if the key exists.

**Initial state:**  
- `numBuckets = 769`

**Execution trace:**  

- **Step 1: `add(1)`**  
  - `hash(1) = 1 % 769 = 1`  
  - Bucket 1 is empty → insert `1` as the head of the linked list.  

- **Step 2: `add(2)`**  
  - `hash(2) = 2 % 769 = 2`  
  - Bucket 2 is empty → insert `2` as the head of the linked list.  

- **Step 3: `contains(1)`**  
  - Traverse bucket 1 → find `1` → return `true`.  

- **Step 4: `contains(3)`**  
  - Traverse bucket 3 → empty → return `false`.  

- **Step 5: `add(2)`**  
  - `hash(2) = 2` → bucket 2 already contains `2` → do nothing.  

- **Step 6: `contains(2)`**  
  - Traverse bucket 2 → find `2` → return `true`.  

- **Step 7: `remove(2)`**  
  - Traverse bucket 2 → find `2` → remove the node.  

- **Step 8: `contains(2)`**  
  - Traverse bucket 2 → no `2` → return `false`.

## 5. Complexity Analysis

- **Time Complexity:**  
  - **Average Case:** $O(1)$ for all operations (assuming uniform distribution of keys).  
  - **Worst Case:** $O(n)$ if all keys hash to the same bucket (linked list becomes a single long chain).  

- **Space Complexity:**  
  - $O(n)$, where $n$ is the number of keys inserted.

## 6. Code Implementation

```cpp
struct Node {
    int key;
    Node* next;
    Node(int k) : key(k), next(nullptr) {}
};

class MyHashSet {
private:
    Node* buckets;
    int numBuckets;
    int hash(int key) {
        return key % numBuckets;
    }
public:
    MyHashSet() {
        numBuckets = 769;
        buckets = new Node*[numBuckets]();
    }
    
    void add(int key) {
        int index = hash(key);
        Node* node = new Node(key);
        node->next = buckets[index];
        buckets[index] = node;
    }
    
    void remove(int key) {
        int index = hash(key);
        Node* curr = buckets[index];
        Node* prev = nullptr;
        while (curr != nullptr) {
            if (curr->key == key) {
                if (prev == nullptr) {
                    buckets[index] = curr->next;
                } else {
                    prev->next = curr->next;
                }
                delete curr;
                return;
            }
            prev = curr;
            curr = curr->next;
        }
    }
    
    bool contains(int key) {
        int index = hash(key);
        Node* curr = buckets[index];
        while (curr != nullptr) {
            if (curr->key == key) {
                return true;
            }
            curr = curr->next;
        }
        return false;
    }
};
```
