## 1. Problem Statement

> You are given two **non-empty** linked lists representing two non-negative integers. The digits are stored in **reverse order**, and each of their nodes contains a single digit. Add the two numbers and return the sum as a linked list.  
>  
> You may assume the two numbers do not contain any leading zero, except the number 0 itself.  
>  
> **Example 1:**  
> Input: `l1 = [2,4,3]`, `l2 = [5,6,4]`  
> Output: `[7,0,8]`  
> Explanation: `342 + 465 = 807`.  
>  
> **Example 2:**  
> Input: `l1 = [0]`, `l2 = [0]`  
> Output: `[0]`  
>  
> **Example 3:**  
> Input: `l1 = [9,9,9,9,9,9,9]`, `l2 = [9,9,9,9]`  
> Output: `[8,9,9,9,0,0,0,1]`

## 2. Constraints & Key Observations

- **Constraints:**  
    - The number of nodes in each linked list is in the range `[1, 100]`.  
    - `0 <= Node.val <= 9`  
    - It is guaranteed that the list represents a number that does not have leading zeros.  

- **What constraints tell us:**  
    - Input lists are guaranteed to be non-empty, so no need to handle empty inputs.  
    - Maximum length of 100 ensures that even brute-force approaches are acceptable, but optimal solutions are still preferred.  

- **Key observations:**  
    - Digits are stored in reverse order, so the head of the list is the least significant digit.  
    - The sum must be computed digit by digit, starting from the least significant digit (head of the list).  
    - Carry must be tracked and propagated to the next digit.  

- **Edge cases to handle (based on actual constraints):**  
    - Lists of unequal length (e.g., `l1 = [1,2,3]`, `l2 = [4,5]`).  
    - Carry that propagates beyond the end of both lists (e.g., `l1 = [9]`, `l2 = [9]` → sum is `[8, 1]`).  
    - Input lists with all digits 9 (e.g., `l1 = [9,9]`, `l2 = [9,9]` → sum is `[8,9,1]`).

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:**  
  We can process both linked lists simultaneously, adding corresponding digits and handling carry as we go.  

- **Algorithm invariant:**  
  At any point in the iteration, the current sum of digits (plus carry) is correctly represented in the result list.  

- **Why this works:**  
  By iterating through both lists in parallel and using a carry variable, we ensure that all digits are processed in the correct order, and the final result is built incrementally.  

### 3.2 Algorithm Strategy

1. **Initialize a dummy head node** to simplify the result list construction.  
2. **Iterate through both lists simultaneously** using a `while` loop that continues as long as either list has nodes or there is a carry.  
3. **Sum the current digits** from both lists (if available) and add the carry.  
4. **Compute the new digit** and update the carry for the next iteration.  
5. **Create a new node** for the result list with the computed digit and link it to the result.  
6. **Move to the next node** in both input lists (if available).

## 6. Code

```cpp
struct ListNode {
    int val;
    ListNode *next;
    ListNode() : val(0), next(nullptr) {}
    ListNode(int x) : val(x), next(nullptr) {}
    ListNode(int x, ListNode *next) : val(x), next(next) {}
};

class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        ListNode dummy(0);
        ListNode* temp = &dummy;
        int carry = 0;

        while (l1 || l2 || carry) {
            int sum = carry;
            if (l1) {
                sum += l1->val;
                l1 = l1->next;
            }
            if (l2) {
                sum += l2->val;
                l2 = l2->next;
            }

            carry = sum / 10;
            temp->next = new ListNode(sum % 10);
            temp = temp->next;
        }

        return dummy.next;
    }
};
```

## 8. Key Takeaways

- **Carry Handling:** Always track carry when adding digits, even if it propagates beyond the end of both lists.  
- **Dummy Node:** Simplifies the process of building the result list by avoiding edge cases for the first node.  
- **Null Checks:** Ensure that the loop continues even if one list is shorter than the other.  
- **Digit Constraints:** Each node must store a single digit (0–9), so use modulo and division operations to extract the digit and carry.
