## 1. Problem Statement

> Alice and Bob take turns playing a game, with Alice starting first.  
>  
> Initially, there is a number `n` on the chalkboard. On each player's turn, that player makes a move consisting of:  
>  
> - Choosing any integer `x` with `0 < x < n` and `n % x == 0`.  
> - Replacing the number `n` on the chalkboard with `n - x`.  
>  
> Also, if a player cannot make a move, they lose the game.  
>  
> Return `true` if and only if Alice wins the game, assuming both players play optimally.  

**Example 1:**  
Input: `n = 2`  
Output: `true`  
Explanation: Alice chooses `1`, and Bob has no more moves.  

**Example 2:**  
Input: `n = 3`  
Output: `false`  
Explanation: Alice chooses `1`, Bob chooses `1`, and Alice has no more moves.

## 2. Constraints & Key Observations

- **Constraints:**  
    - `1 <= n <= 1000`  

- **What constraints tell us:**  
    - `n` is small enough that brute-force simulation is feasible, but the optimal solution is mathematical and independent of `n`'s size.  

- **Key observations:**  
    - The outcome depends solely on whether `n` is even or odd.  
    - For even `n`, Alice can always win by choosing `x = 1`, making `n` odd and forcing Bob into a losing position.  
    - For odd `n`, any valid move reduces `n` to an even number, giving the next player a winning position.  

- **Edge cases to handle (based on actual constraints):**  
    - `n = 1`: Alice cannot make a move and loses.  
    - `n = 2`: Alice wins by choosing `x = 1`.  
    - `n = 3`: Alice loses after choosing `x = 1`.

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** The game outcome is determined by the parity of `n`.  
- **Algorithm invariant:** If `n` is even, Alice wins; if `n` is odd, Bob wins.  
- **Why this works:**  
    - For even `n`, Alice can always subtract `1` (a valid divisor), making `n` odd. Bob is then forced into a losing position.  
    - For odd `n`, any valid `x` must be odd (since `n % x == 0`), and subtracting an odd number from an odd number results in an even number, which is a winning position for the next player.  

### 3.2 Algorithm Strategy

1. Check if `n` is even.  
2. Return `true` if even, `false` otherwise.

## 4. Example Walkthrough

**Execution trace:**  
- Alice chooses `x = 1` (valid divisor of `2`).  
- `n` becomes `2 - 1 = 1`.  
- Bob has no valid moves (`x` must be between `0` and `1`, but `1 % 1 == 0` is not allowed).  
- **Final result:** `true` (Alice wins).

**Initial state:** `n = 3`  

**Execution trace:**  
- Alice chooses `x = 1` (valid divisor of `3`).  
- `n` becomes `3 - 1 = 2`.  
- Bob chooses `x = 1` (valid divisor of `2`).  
- `n` becomes `2 - 1 = 1`.  
- Alice has no valid moves.  
- **Final result:** `false` (Alice loses).

## 5. Complexity Analysis

- **Time Complexity:** $O(1)$  
    - **Why:** Only a single modulus operation is performed.  

- **Space Complexity:** $O(1)$  
    - **Why:** No additional data structures are used; only a single boolean is returned.

## 6. Code Solution (C++)

```cpp
class Solution {

public:

    bool divisorGame(int n) {

        return n % 2 == 0;

    }

};
```
