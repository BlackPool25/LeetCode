## 1. Problem Statement

> **Reverse bits of a given 32 bits signed integer.**  
>  
> **Example 1:**  
> **Input:** `n = 43261596`  
> **Output:** `964176192`  
> **Explanation:**  
>  
> | Integer | Binary |  
> |---|---|  
> | 43261596 | 00000010100101000001111010011100 |  
> | 964176192 | 00111001011110000010100101000000 |  
>  
> **Example 2:**  
> **Input:** `n = 2147483644`  
> **Output:** `1073741822`  
> **Explanation:**  
>  
> | Integer | Binary |  
> |---|---|  
> | 2147483644 | 01111111111111111111111111111100 |  
> | 1073741822 | 00111111111111111111111111111110 |

## 2. Constraints & Key Observations

- **Constraints:**
    - `0 <= n <= 2^31 - 2`
    - `n` is even.

- **What constraints tell us:**
    - `n` is guaranteed to be a 32-bit integer (even though it's signed, the solution treats it as unsigned).
    - The input is always even, which ensures the least significant bit is always `0` (but the solution still processes all 32 bits).

- **Key observations:**
    - The solution must reverse **exactly 32 bits**, even if the input has leading zeros.
    - The output is a 32-bit unsigned integer, which is why the solution uses `unsigned int`.

- **Edge cases to handle (based on actual constraints):**
    - `n = 0` → output is `0` (all bits are zero).
    - `n = 1` → output is `2^31` (but this is not allowed due to the constraint that `n` is even).
    - `n = 2^31 - 2` → output is a reversed version of the binary representation of this value.

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:**  
  Each bit in the input can be processed one at a time, starting from the least significant bit (LSB) and building the reversed number from the most significant bit (MSB) to LSB.

- **Algorithm invariant:**  
  After each iteration, `x` contains the reversed bits of the first `i+1` bits of `m`.

- **Why this works:**  
  By shifting `x` left by 1 and OR-ing with the LSB of `m`, we build the reversed number bit by bit. Shifting `m` right by 1 ensures that we process the next bit in the next iteration.

### 3.2 Algorithm Strategy

1. Convert the input `n` to an `unsigned int` to handle all 32 bits properly.
2. Initialize `x` to `0` (this will store the reversed bits).
3. Loop 32 times (for each bit in the 32-bit integer):
    - Shift `x` left by 1 to make room for the next bit.
    - Mask `m` with `1` to extract the current LSB.
    - OR the result into `x`.
    - Shift `m` right by 1 to process the next bit.
4. Return `x` as the reversed integer.

## 4. Example Walkthrough

**Input:** `n = 43261596`  
**Binary:** `00000010100101000001111010011100`  
**Output:** `964176192`

**Initial state:**
- `x = 0`
- `m = 43261596` (as `unsigned int`)

**Execution trace:**

- **Step 1:**  
  - `x = (0 << 1) | (m & 1)` → `0 | 0` → `0`  
  - `m = m >> 1` → `21630798`  
- **Step 2:**  
  - `x = (0 << 1) | (m & 1)` → `0 | 0` → `0`  
  - `m = m >> 1` → `10815399`  
- **Step 3:**  
  - `x = (0 << 1) | (m & 1)` → `0 | 1` → `1`  
  - `m = m >> 1` → `5407699`  
- **... (continue for 32 steps)**  
- **Final result:**  
  - `x = 964176192`

## 5. Complexity Analysis

- **Time Complexity:** $O(1)$  
  - **Why:** The loop runs exactly 32 times, independent of the input size.

- **Space Complexity:** $O(1)$  
  - **Why:** Only a few variables (`x`, `m`) are used, and their size is constant.

## 6. Pattern Recognition

### Reusable Template

```cpp
unsigned int reverseBits(int n) {
    unsigned int x = 0;
    unsigned int m = n;
    for (int i = 0; i < 32; ++i) {
        x = (x << 1) | (m & 1);
        m >>= 1;
    }
    return x;
}
```

### Specific Insights

- **Bit Manipulation - Reversing Bits:**  
  This pattern involves using bitwise operations (`<<`, `>>`, `&`, `|`) to process each bit individually and build the result incrementally.

- **Key Insight:**  
  The solution avoids using string manipulation or array-based approaches by directly working with bit-level operations, which is both efficient and elegant.
