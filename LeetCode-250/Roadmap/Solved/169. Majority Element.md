

# 169. Majority Element

## 0. Problem Metadata

- **Difficulty:** Medium
- **Topics/Tags:** Array, Hash Table, Sorting
- **Pattern Category:** Boyer‑Moore Voting Algorithm (Counter Cancellation)
- **LeetCode Link:** https://leetcode.com/problems/majority-element/

## 1. Problem Statement

> **Given an array `nums` of size `n`, return the majority element.**  
> The majority element is the element that appears more than ⌊n / 2⌋ times. You may assume that the majority element always exists in the array.
> 
> **Example 1:**
> 
> **Input:** nums = [3,2,3]  
> **Output:** 3
> 
> **Example 2:**
> 
> **Input:** nums = [2,2,1,1,1,2,2]  
> **Output:** 2
> 
> **Constraints:**
> 
> - `n == nums.length`  
> - `1 <= n <= 5 * 10^4`  
> - `-10^9 <= nums[i] <= 10^9`  
> - The input is generated such that a majority element will exist in the array.
> 
> **Follow‑up:** Could you solve the problem in linear time and in O(1) space?

## 2. Constraints & Key Observations

- **Constraints:**
  - `1 ≤ n ≤ 5·10⁴`
  - `-10⁹ ≤ nums[i] ≤ 10⁹`
  - A majority element is guaranteed to exist.
- **What constraints tell us:**
  - `n` is large enough that an O(n²) algorithm (e.g., counting each element with a nested loop) will be too slow.
  - Because the majority element appears more than half the time, a single‑pass algorithm that uses only a few variables can be sufficient.
- **Key observations:**
  - Any element that is not the majority can be “paired” with a different element and both can be ignored for the purpose of finding the majority.
  - After cancelling out all such pairs, the element that remains must be the majority.
- **Edge cases:**
  - Array of length 1 (the sole element is the majority).
  - All elements identical.
  - Majority element appears exactly `⌊n/2⌋ + 1` times.

## 3. Solution Development

### 3.1 Core Intuition

The **Boyer‑Moore Voting Algorithm** relies on a simple cancellation principle:  
*Whenever we see two different elements, we can pair them off and ignore both.*  
After processing the entire array, the element that survives this cancellation process must be the majority.

**Invariant:**  
`curMaj.second` (the counter) is always non‑negative.  
When it becomes negative, the current candidate cannot be the majority and we reset the candidate to the current element.

### 3.2 Algorithm Strategy

1. **Initialize** a candidate (`curMaj.first`) and a counter (`curMaj.second`) with the first element of the array and count = 1.
2. **Iterate** over the rest of the array:
   - If the current element equals the candidate, increment the counter.
   - Otherwise, decrement the counter.
   - If the counter drops below zero, reset the candidate to the current element and set the counter to 1.
3. **Return** the candidate after the loop; it is guaranteed to be the majority.

## 3. Example Walkthrough

### Example 1: `nums = [3, 2, 3]`

| Step | i | nums[i] | curMaj.first | curMaj.second |
|------|---|---------|--------------|---------------|
| 0    | 0 | 3       | 3            | 1             |
| 1    | 1 | 2       | 3            | 0             | (decremented, still ≥ 0) |
| 2    | 2 | 3       | 3            | 1             | (incremented) |

Result: `curMaj.first` = **3**.

### Example 2: `nums = [2,2,1,1,1,2,2]`

| Step | i | nums[i] | curMaj.first | curMaj.second |
|------|---|---------|--------------|---------------|
| 0    | 0 | 2       | 2            | 1             |
| 1    | 1 | 2       | 2            | 2             |
| 2    | 2 | 1       | 2            | 1             |
| 3    | 3 | 1       | 2            | 0             |
| 4    | 4 | 1       | 2            | -1            | (reset) → candidate = 1, count = 1 |
| 5    | 5 | 2       | 1            | 0             |
| 6    | 6 | 2       | 1            | 1             |

Result: `curMaj.first` = **2**.

## 3. Complexity Analysis

- **Time:** O(n) – one pass over the array.  
- **Space:** O(1) – only a fixed pair of integers is used.

## 6. Code Solution (C++)

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        // curMaj.first  → current candidate
        // curMaj.second → current counter
        pair<int, int> curMaj;
        curMaj.first = nums[0];   // start with the first element as candidate
        curMaj.second = 1;        // initial count

        for (int i = 1; i < nums.size(); i++) {
            if (nums[i] == curMaj.first) {
                curMaj.second++;          // same element → increase counter
            } else {
                curMaj.second--;          // different element → cancel one
                if (curMaj.second < 0) {  // counter went negative → reset
                    curMaj.first = nums[i];
                    curMaj.second = 1;
                }
            }
        }
        return curMaj.first;  // guaranteed to be the majority element
    }
};
```

## 7. Key Takeaways & Pattern Recognition

### Pattern Applies When

- You need to find an element that appears more than a fixed fraction of the array (e.g., > n/2, > n/3).
- The input guarantees that such an element exists.
- You want a linear‑time, constant‑space solution.

### Pattern Structure (Boyer‑Moore Voting)

```cpp
candidate = nums[0];
count     = 1;
for (int i = 1; i < nums.size(); ++i) {
    if (nums[i] == candidate) count++;
    else                      count--;
    if (count < 0) {
        candidate = nums[i];
        count     = 1;
    }
}
return candidate;   // majority element
```

### Core Insights

1. **Cancellation** – every time we see a different element, we decrement the counter; pairs of different elements cancel each other out.
2. **Reset on negative** – when the counter becomes negative, the current candidate cannot be the majority; we immediately adopt the current element as a new candidate and reset the counter to 1.
3. **Invariant** – as long as the counter is non‑negative, the current candidate is a *potential* majority element.

### Common Mistake

- Forgetting to reset the counter when it drops below zero.  
  This leaves the algorithm with an incorrect candidate and wrong answer.
