## 1. Problem Statement

> Given an array of integers `temperatures` represents the daily temperatures, return an array `answer` such that `answer[i]` is the number of days you have to wait after the `ith` day to get a warmer temperature. If there is no future day for which this is possible, keep `answer[i] == 0` instead.

**Example 1:**  
Input: `temperatures = [73,74,75,71,69,72,76,73]`  
Output: `[1,1,4,2,1,1,0,0]`  
Explanation: For example, the first day (73) has a warmer temperature on the next day (74), so the answer is 1.

**Example 2:**  
Input: `temperatures = [30,40,50,60]`  
Output: `[1,1,1,0]`  

**Example 3:**  
Input: `temperatures = [30,60,90]`  
Output: `[1,1,0]`

## 2. Constraints & Key Observations

- **Constraints:**
    - `1 <= temperatures.length <= 10^5`
    - `30 <= temperatures[i] <= 100`

- **What constraints tell us:**
    - `n <= 10^5` implies O(n²) approaches are infeasible; must use O(n) or O(n log n) algorithms.
    - Temperature values are bounded (30–100), but this doesn't directly affect the algorithm.

- **Key observations:**
    - The problem is equivalent to finding the **next greater element** for each index.
    - A **monotonic stack** (specifically, a decreasing stack) is ideal for this type of problem.
    - Each index is pushed to the stack **once**, and popped **once** at most.

- **Edge cases to handle:**
    - All temperatures are the same (e.g., `[30,30,30]` → `[0,0,0]`)
    - Temperatures are strictly increasing (e.g., `[30,40,50]` → `[1,1,0]`)
    - Temperatures are strictly decreasing (e.g., `[100,90,80]` → `[0,0,0]`)

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Use a **monotonic stack** to track indices of temperatures that have not yet found a warmer day.
- **Algorithm invariant:** The stack always contains indices in **strictly decreasing** order of temperature.
- **Why this works:** When a new temperature is higher than the temperature at the top of the stack, we can resolve all previous indices that are lower than it, as they now have their "warmer day" found.

### 3.2 Algorithm Strategy

1. Initialize an empty stack to store indices of temperatures.
2. Iterate through each temperature in the array:
    - While the stack is not empty and the current temperature is **greater** than the temperature at the index on top of the stack:
        - Pop the index from the stack.
        - Calculate the number of days between the current index and the popped index.
        - Store this value in the answer array at the popped index.
    - Push the current index to the stack.
3. After processing all temperatures, any remaining indices in the stack have no warmer day in the future, so their answer remains 0.

## 4. Example Walkthrough

**Input:** `temperatures = [73,74,75,71,69,72,76,73]`  
**Initial state:**
- `answer = [0, 0, 0, 0, 0, 0, 0, 0]`

**Execution trace:**

- **Step 0 (i=0):**  
  `evalStack` is empty → push `0`

- **Step 1 (i=1):**  
  `temperatures[0] = 73 < 74` → pop `0`, set `answer[0] = 1 - 0 = 1`  
  `evalStack = empty` → push `1`  
  `evalStack = [1]`

- **Step 2 (i=2):**  
  `temperatures[1] = 74 < 75` → pop `1`, set `answer[1] = 2 - 1 = 1`  
  `evalStack = empty` → push `2`  
  `evalStack = [2]`

- **Step 3 (i=3):**  
  `temperatures[2] = 75 > 71` → push `3`  
  `evalStack = [2, 3]`

- **Step 4 (i=4):**  
  `temperatures[3] = 71 > 69` → push `4`  
  `evalStack = [2, 3, 4]`

- **Step 5 (i=5):**  
  `temperatures[4] = 69 < 72` → pop `4`, set `answer[4] = 5 - 4 = 1`  
  `temperatures[3] = 71 < 72` → pop `3`, set `answer[3] = 5 - 3 = 2`  
  `evalStack = [2]` → push `5`

- **Step 6 (i=6):**  
  `temperatures[5] = 72 < 76` → pop `5`, set `answer[5] = 6 - 5 = 1`

  `temperatures[6] = 76 > 73` → push `7`  
  `evalStack = [6, 7]`

## 5. Complexity Analysis

- **Time Complexity:** O(n)  
  Each index is pushed and popped from the stack at most once.
- **Space Complexity:** O(n)  
  Stack and answer array both use O(n) space.

---

## 6. Code

```cpp
vector<int> dailyTemperatures(vector<int>& temperatures) {
    vector<int> answer(temperatures.size(), 0);
    stack<int> evalStack;

    for (int i = 0; i < temperatures.size(); ++i) {
        while (!evalStack.empty() && temperatures[i] > temperatures[evalStack.top()]) {
            int prevIndex = evalStack.top();
            answer[prevIndex] = i - prevIndex;
            evalStack.pop();
        }
        evalStack.push(i);
    }

    return answer;
}
```

## 7. Pattern Recognition

### **Monotonic Stack - Next Greater Element Framework**

```cpp
vector<int> nextGreaterElement(vector<int>& nums) {
    vector<int> result(nums.size(), 0);
    stack<int> s;

    for (int i = 0; i < nums.size(); ++i) {
        while (!s.empty() && nums[i] > nums[s.top()]) {
            int prevIndex = s.top();
            result[prevIndex] = nums[i];
            s.pop();
        }
        s.push(i);
    }

    return result;
}
```

## 8. Key Takeaways

- **Monotonic stacks** are ideal for problems requiring the **next greater element**.
- The stack maintains a **strictly decreasing** order of temperatures.
- Each index is processed **once**, leading to **O(n)** time complexity.
- **Common mistakes:**
  - Forgetting to pop from the stack when a greater element is found.
  - Not maintaining the invariant of the stack (must be strictly decreasing).
