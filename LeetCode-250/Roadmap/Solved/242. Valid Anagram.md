## 1. Problem Statement

> **Given two strings ` s ` and ` t `, return ` true ` if ` t ` is an anagram of ` s `, and ` false ` otherwise.**

> **Example 1:**

> **Input:** s = "anagram", t = "nagaram"

> **Output:** true

> **Example 2:**

> **Input:** s = "rat", t = "car"

> **Output:** false

> **Constraints:**

> - `1 <= s.length, t.length <= 5 * 10^4`
> - `s` and `t` consist of lowercase English letters.

> **Follow up:** What if the inputs contain Unicode characters? How would you adapt your solution to such a case?

## 2. Constraints & Key Observations

- **Constraints:**
  - `1 ≤ s.length, t.length ≤ 5·10⁴`
  - `s` and `t` contain only lowercase English letters (`a`–`z`).

- **What constraints tell us:**
  - The strings can be up to 50 000 characters long, so an **O(n)** solution is required.
  - Since the alphabet size is fixed (26 letters), a frequency array of size 26 would also be O(1) space, but a hash map works equally well and handles arbitrary Unicode in the follow‑up.

- **Key observations:**
  - Two strings are anagrams iff they contain exactly the same multiset of characters.
  - The order of characters does not matter; only the counts do.
  - If the lengths differ, they cannot be anagrams.

- **Edge cases to handle:**
  - Strings of different lengths.
  - Strings that are identical.
  - Strings that contain all the same character.
  - Strings that differ by a single character count.

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Count each character in `s` and decrement the count while scanning `t`. If any count goes negative, `t` has an extra character.
- **Algorithm invariant:** After processing the first `i` characters of `t`, the map holds the difference between the counts of `s` and those of the processed prefix of `t`.  
- **Why this works:** If `t` is an anagram, every decrement will exactly cancel a previous increment, leaving all counts zero at the end.

### 3.2 Algorithm Strategy

1. **Length check** – If `s` and `t` differ in length, return `false` immediately.
2. **Build frequency map for `s`** – Iterate over `s`, incrementing the count for each character.
3. **Validate against `t`** – Iterate over `t`, decrementing the count for each character.  
   - If a count becomes negative, `t` contains an extra character → return `false`.
4. **All checks passed** – Return `true`.

## 5. Complexity Analysis

- **Time Complexity:** $O(n)$  
  - We traverse each string once; each map operation is $O(1)$ on average.
- **Space Complexity:** $O(k)$ where $k$ is the number of distinct characters.  
  - For lowercase English letters, $k = 26$ → $O(1)$ space.  
  - For Unicode, $k$ could be larger but still bounded by the alphabet size.

## 6. Code Solution (C++)

```cpp
class Solution {
public:
    bool isAnagram(string s, string t) {
        if(s.length() != t.length()) return false;   // Length mismatch → not anagram
        unordered_map<char,int> dic1;                 // Frequency map for s
        for(char c : s) dic1[c]++;                    // Count each char in s
        for(char c : t){                              // Decrement counts using t
            dic1[c]--;                                // Remove one occurrence
            if(dic1[c] < 0 ) return false;            // Extra char in t
        }
        return true;                                  // All counts matched
    }
};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**
  - You need to compare the multiset of elements between two collections.
  - The order of elements is irrelevant, only the counts matter.
  - The input size is large enough that an $O(n)$ solution is required.
  - You can use a hash map (or array) to store frequencies.

- **Pattern Structure (reusable template):**

```cpp
// Hash Map – Frequency Count
unordered_map<key_type, int> freq;

// Build frequency map from first collection
for(const auto& item : first) freq[item]++;

// Validate against second collection
for(const auto& item : second) {
    freq[item]--;
    if(freq[item] < 0) return false;  // Extra element found
}

return true;  // All counts matched
```

### 💡 Key Insights

- **Frequency balancing** – Increment for one string, decrement for the other; any imbalance immediately signals a mismatch.
- **Early exit** – Checking for negative counts during the second pass avoids a full scan after processing.
- **Space trade‑off** – Using an array of size 26 would reduce constant factors but a hash map generalizes to Unicode.
