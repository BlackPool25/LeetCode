

# 21. Merge Two Sorted Lists

- **Difficulty:** Easy

## 1. Problem Statement

> You are given the heads of two sorted linked lists `list1` and `list2`.  
> Merge the two lists into one **sorted** list. The list should be made by splicing together the nodes of the first two lists.  
> Return the head of the merged linked list.

**Example 1:**  
Input: `list1 = [1,2,4]`, `list2 = [1,3,4]`  
Output: `[1,1,2,3,4,4]`  
Explanation: The merged list is formed by splicing the nodes of both lists in sorted order.

**Example 2:**  
Input: `list1 = []`, `list2 = []`  
Output: `[]`  

**Example 3:**  
Input: `list1 = []`, `list2 = [0]`  
Output: `[0]`

---

## 2. Constraints & Key Observations

- **Constraints:**
    - The number of nodes in both lists is in the range `[0, 50]`.
    - `-100 <= Node.val <= 100`
    - Both `list1` and `list2` are sorted in **non-decreasing** order.

- **What constraints tell us:**
    - Input size is small, so even $O(n \cdot m)$ algorithms would work.
    - Both lists are guaranteed to be sorted, which is the key to the solution.

- **Key observations:**
    - Since both lists are sorted, we can merge them by comparing the current nodes of each list.
    - The merged list must maintain the sorted order, which can be achieved by always appending the smaller of the two current nodes.

- **Edge cases to handle:**
    - One or both lists are empty.
    - One list is completely exhausted before the other.

---

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Since both lists are sorted, we can merge them by comparing the current nodes and appending the smaller one to the result.
- **Algorithm invariant:** At any point, the merged list up to the current `temp` pointer is always sorted.
- **Why this works:** By always appending the smaller of the two current nodes, we ensure that the merged list remains sorted.

### 3.2 Algorithm Strategy

1. Initialize a **dummy node** to simplify edge cases (e.g., empty lists).
2. Use a `temp` pointer to build the merged list iteratively.
3. While both `list1` and `list2` have nodes:
    - Compare the current values of `list1` and `list2`.
    - Append the smaller node to the merged list and advance the corresponding pointer.
4. After one list is exhausted, append the remaining nodes from the other list.

---

## 4. Example Walkthrough

**Input:** `list1 = [1,2,4]`, `list2 = [1,3,4]`  
**Steps:**
1. Initialize `dummy` and `temp` at `dummy`.
2. Compare `1` (list1) vs `1` (list2) → append `1` (list2), move `list2` to `3`.
3. Compare `1` (list1) vs `3` (list2) → append `1` (list1), move `list1` to `2`.
4. Compare `2` (list1) vs `3` (list2) → append `2` (list1), move `list1` to `4`.
5. Compare `4` (list1) vs `3` (list2) → append `3` (list2), move `list2` to `4`.
6. Compare `4` (list1) vs `4` (list2) → append `4` (list1), move `list1` to `null`.
7. Append remaining `4` (list2) to the merged list.

**Result:** `[1,1,2,3,4,4]`

---

## 5. Complexity Analysis

- **Time Complexity:** $O(n + m)$, where $n$ and $m$ are the lengths of `list1` and `list2`.
- **Space Complexity:** $O(1)$ (excluding the dummy node, which is constant space).

---

## 6. Code Solution

```cpp
struct ListNode* mergeTwoLists(struct ListNode* list1, struct ListNode* list2) {
    struct ListNode dummy;
    struct ListNode* temp = &dummy;
    
    while (list1 && list2) {
        if (list1->val < list2->val) {
            temp->next = list1;
            list1 = list1->next;
        } else {
            temp->next = list2;
            list2 = list2->next;
        }
        temp = temp->next;
    }
    
    temp->next = list1 ? list1 : list2;
    
    return dummy.next;
}
```

## 7. Pattern Recognition

- **Pattern Name:** Two Pointers - Same Direction (Independent)  
- **Reusable Framework:**

- **When to use this pattern:**

## 8. Key Takeaways

- **Insight:** The sorted property of the input lists allows for a simple comparison-based merge.
- **Technique:** Use a dummy node to simplify the logic for handling empty lists or the end of a list.
- **Common Mistake:** Forgetting to handle the case where one list is exhausted before the other.
