## 1. Problem Statement

> Given an array of integers `nums` which is sorted in ascending order, and an integer `target`, write a function to search `target` in `nums`. If `target` exists, then return its index. Otherwise, return `-1`.  
>  
> You must write an algorithm with `O(log n)` runtime complexity.  
>  
> **Example 1:**  
> Input: `nums = [-1,0,3,5,9,12]`, `target = 9`  
> Output: `4`  
> Explanation: `9` exists in `nums` and its index is `4`  
>  
> **Example 2:**  
> Input: `nums = [-1,0,3,5,9,12]`, `target = 2`  
> Output: `-1`  
> Explanation: `2` does not exist in `nums` so return `-1`

## 2. Constraints & Key Observations

- **Constraints:**  
    - `1 <= nums.length <= 10^4`  
    - `-10^4 < nums[i], target < 10^4`  
    - All the integers in `nums` are **unique**.  
    - `nums` is sorted in ascending order.  

- **What constraints tell us:**  
    - Sorted array with unique elements guarantees binary search is applicable.  
    - `O(log n)` runtime is required, ruling out linear scans.  

- **Key observations:**  
    - The array is guaranteed to be sorted and have no duplicates, so binary search can be applied directly.  
    - The target is either present (return index) or not (return -1).  

- **Edge cases to handle (based on actual constraints):**  
    - Target is the first element (`nums[0]`).  
    - Target is the last element (`nums[nums.size()-1]`).  
    - Target is not in the array.

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Binary search works by repeatedly halving the search space, leveraging the sorted property of the array.  
- **Algorithm invariant:** At any point, the target (if present) must lie within the current `[front, rear]` range.  
- **Why this works:** The sorted and unique properties ensure that comparing the middle element with the target allows us to eliminate half the remaining elements in each iteration.  

### 3.2 Algorithm Strategy

1. Initialize two pointers: `front` at the start of the array, and `rear` at the end.  
2. While `front <= rear`, compute the middle index `mid`.  
3. If `nums[mid] == target`, return `mid`.  
4. If `nums[mid] < target`, move `front` to `mid + 1` (target must be in the right half).  
5. Else, move `rear` to `mid - 1` (target must be in the left half).  
6. If the loop ends without finding the target, return `-1`.  

---

## 4. Example Walkthrough

**Input:** `nums = [-1,0,3,5,9,12]`, `target = 9`  

**Initial state:**  
- `front = 0`, `rear = 5`  

**Execution trace:**  
- **Step 1:** `mid = 2` → `nums[2] = 3 < 9` → `front = 3`  
- **Step 2:** `mid = 3 + (5-3)/2 = 4` → `nums[4] = 9 == target` → return `4`  

**Final result:** `4`  

---

## 5. Complexity Analysis

- **Time Complexity:** $O(\log n)$  
    - Why: Each iteration halves the search space, leading to logarithmic steps.  
- **Space Complexity:** $O(1)$  
    - Why: Only constant variables (`front`, `rear`, `mid`) are used, independent of input size.  

---

## 6. Code Solution (C++)

```cpp
class Solution {

public:

    int search(vector<int>& nums, int target) {

        int front = 0;

        int rear = nums.size()-1;

        while(front <= rear){

            int mid = front + (rear - front)/2;

            if(nums[mid] == target) return mid;

            else if(nums[mid] < target) front = mid + 1;

            else rear = mid - 1;

        }

        return -1;

    }

};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**  
    - The input is a **sorted array with unique elements**.  
    - You need to **search for a specific value** with **logarithmic time complexity**.  
    - The problem guarantees **no duplicates** and **ascending order**.  

- **Pattern Structure (reusable template):**

```cpp
// Binary Search - Divide and Conquer (Sorted Array with Unique Elements)
// Maintain a search range [front, rear] and narrow it down by half each step

int front = 0;  // Start of search range
int rear = nums.size() - 1;  // End of search range

while (front <= rear) {
    int mid = front + (rear - front) / 2;  // Avoid overflow
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) front = mid + 1;  // Target is in right half
    else rear = mid - 1;  // Target is in left half
}

return -1;  // Target not found
```

### 💡 Key Insights

- **Avoid using `(front + rear) / 2`** to prevent potential integer overflow.  
- **The loop condition `front <= rear`** ensures all elements are considered.  
- **Common mistake:** Forgetting to update both `front` and `rear` correctly based on the comparison.
