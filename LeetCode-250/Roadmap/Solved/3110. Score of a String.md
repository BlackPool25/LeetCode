## 1. Problem Statement

> You are given a string `s`. The **score** of a string is defined as the sum of the absolute difference between the **ASCII** values of adjacent characters.  
>  
> **Example 1:**  
> Input: `s = "hello"`  
> Output: `13`  
> Explanation:  
> The **ASCII** values of the characters in `s` are: `'h' = 104`, `'e' = 101`, `'l' = 108`, `'o' = 111`. So, the score of `s` would be `|104 - 101| + |101 - 108| + |108 - 108| + |108 - 111| = 3 + 7 + 0 + 3 = 13`.  
>  
> **Example 2:**  
> Input: `s = "zaz"`  
> Output: `50`  
> Explanation:  
> The **ASCII** values of the characters in `s` are: `'z' = 122`, `'a' = 97`. So, the score of `s` would be `|122 - 97| + |97 - 122| = 25 + 25 = 50`.

## 2. Constraints & Key Observations

- **Constraints:**  
    - `2 <= s.length <= 100`  
    - `s` consists only of lowercase English letters.  

- **What constraints tell us:**  
    - The string length is guaranteed to be at least 2, so no need to handle empty strings or single-character cases.  
    - The maximum length of 100 ensures that even a brute-force approach is acceptable.  

- **Key observations:**  
    - The score is computed by summing the absolute differences between **every pair of adjacent characters**.  
    - The problem reduces to a simple iteration over the string, with no need for complex data structures or algorithms.  

- **Edge cases to handle (based on actual constraints):**  
    - Strings of length 2 (e.g., `"ab"` → only one pair to compute).  
    - Strings with all identical characters (e.g., `"aaaaa"` → all differences are zero).

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** The score is simply the sum of absolute differences between consecutive characters.  
- **Algorithm invariant:** At each step, the current character and the next character are compared, and their difference is added to the total.  
- **Why this works:** The problem definition directly maps to this approach, requiring no additional logic or optimization.  

### 3.2 Algorithm Strategy

1. Initialize a variable `score` to 0.  
2. Iterate through the string from the first character to the second-to-last character.  
3. For each character at index `i`, compute the absolute difference between `s[i]` and `s[i+1]`, and add it to `score`.  
4. Return the final value of `score`.

**Execution trace:**

- **Step 4:** Compare `'l'` (108) and `'o'` (111) → `|108 - 111| = 3` → `score = 13`  

**Final result:** `13`

## 5. Complexity Analysis

- **Time Complexity:** $O(n)$, where $n$ is the length of the string.  
    - **Why:** A single pass through the string with constant-time operations per character.  

- **Space Complexity:** $O(1)$  
    - **Why:** Only a single integer variable (`score`) is used, regardless of input size.

## 6. Code Solution (C++)

```cpp
class Solution {
 public:
    int scoreOfString(string s) {
        int score = 0;
        for(int i=0; i<s.length()-1 ; i++){
            score += abs(static_cast<int>(s[i]) - static_cast<int>(s[i+1]));
        }
        return score;
    }
};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**  
    - You need to process **adjacent elements** in a sequence (e.g., array, string, linked list).  
    - The problem requires **iterating through pairs** of elements with a fixed relationship (e.g., consecutive characters, neighboring nodes).  

- **Pattern Structure (reusable template):**

```cpp
// Iterative Traversal - Adjacent Elements
// Traverse the string from index 0 to length-2, comparing each character with its next neighbor

int score = 0;
for (int i = 0; i < s.length() - 1; i++) {
    score += abs(static_cast<int>(s[i]) - static_cast<int>(s[i + 1]));
}
return score;
```
