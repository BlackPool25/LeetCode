## 1. Problem Statement

> **Remove Element**  
> Given an integer array `nums` and an integer `val`, remove all occurrences of `val` in `nums` **in‑place**.  
> The order of the elements may be changed. Then return the number of elements in `nums` which are not equal to `val`.  
>  
> Consider the number of elements in `nums` which are not equal to `val` be `k`. To get accepted, you need to do the following things:
> - Change the array `nums` such that the first `k` elements of `nums` contain the elements which are not equal to `val`.  
>   The remaining elements of `nums` are not important as well as the size of `nums`.  
> - Return `k`.  
>

> }
> ```
> If all assertions pass, then your solution will be **accepted**.
>

> **Input:** `nums = [3,2,2,3]`, `val = 3`  
> **Output:** `2`, `nums = [2,2,_,_]`  
> **Explanation:** Your function should return `k = 2`, with the first two elements of `nums` being `2`.

>

> Note that the five elements can be returned in any order.  
> It does not matter what you leave beyond the returned `k` (hence they are underscores).  
>

## 2. Constraints & Edge Cases

| Constraint | Implication for the algorithm |
|------------|------------------------------|
| `nums.length = 0` | The loop never runs; `last = -1` and the function correctly returns `0`. |
| All elements equal `val` | Each element is swapped with the end until `last` moves past `i`; the function returns `0`. |
| No element equals `val` | No swaps occur; `i` simply scans to the end and the function returns `nums.size()`. |
| `val` appears only at the end | The inner `while` never triggers; the array remains unchanged and the function returns the original size. |
| `val` appears multiple times consecutively | The inner `while` handles consecutive `val`s by repeatedly swapping with the current `last` until a non‑`val` is found. |

## 2.1 Key Observations

- Swapping a `val` at the front with an element at the back removes the `val` from the *effective* array without needing to shift all subsequent elements.
- The pointer `last` always points to the last position that may still contain a `val`.  
  Elements **after** `last` are guaranteed to be removed (or already `val`).
- When a swap occurs, the new element at index `i` must be examined again, so `i` is **not** incremented in that iteration.

## 2.2 Solution Development

### Core Intuition

Use **two pointers**:  
- `i` scans from the beginning.  
- `last` starts at the end and moves leftwards whenever a `val` is found at `i`.  
By swapping `nums[i]` with `nums[last]` and decrementing `last`, we effectively “hide” the `val` at the back of the array.  
The invariant maintained is:  
> All elements **after** `last` are either already removed or will never be examined again.

### Algorithm Strategy

1. Initialise `last` to `nums.size() - 1`.  
2. Iterate `i` from `0` up to `last` (inclusive).  
3. While `i <= last` **and** `nums[i] == val`:  
   - Swap `nums[i]` with `nums[last]`.  
   - Decrement `last`.  
   - Do **not** increment `i` because the new element at `i` might also be `val`.  
4. When `nums[i] != val`, increment `i` and continue.  
5. After the loop, `last + 1` equals the number of retained elements (`k`). Return this value.

This is a classic **Two Pointers – Opposite Ends** pattern: one pointer moves forward, the other moves backward only when a swap is necessary.

## 3. Example Walkthrough

### Example 1  
`nums = [3,2,2,3]`, `val = 3`

| Step | `i` | `last` | `nums`          | Action |
|------|-----|--------|-----------------|--------|
| 0    | 0   | 3      | `[3,2,2,3]`     | `nums[0]==val` → swap with `nums[3]` (no change), `last=2` |
| 1    | 0   | 2      | `[3,2,2,3]`     | `nums[0]==val` → swap with `nums[2]` → `[2,2,3,3]`, `last=1` |
| 2    | 0   | 1      | `[2,2,3,3]`     | `nums[0]!=val` → `i=1` |
| 3    | 1   | 1      | `[2,2,3,3]`     | `nums[1]!=val` → `i=2` (now `i > last`) |
| End  | –   | 1      | –               | Return `last+1 = 2` |

## 4. Complexity Analysis

- **Time Complexity:** $O(n)$ – each element is examined at most twice (once by `i`, once by `last`).  
- **Space Complexity:** $O(1)$ – only a few integer variables are used regardless of input size.

## 5. Code Solution

```cpp
class Solution { public: int removeElement(vector<int>& nums, int val) { int last = nums.size() - 1; for(int i = 0; i <= last ; i++){ while(i <= last && nums[i] == val) // Checks the conditions where the last is after the i and also if the value of i is the same as val and if so it swaps { int temp = nums[last]; nums[last] = nums[i]; nums[i] = temp; // Swap both the numbers last--; //decrement last } } return last + 1; // Return the size of the new vector so it's last + 1 } };
```

## 6. Pattern Recognition

**Pattern Category:** Two Pointers – Opposite Ends (Fast‑Slow from opposite ends)

### Reusable Template

```cpp
int left = 0;
int right = array.size() - 1;
for (int left = 0; left <= right; ++left) {
    while (left <= right && /* condition on left element */) {
        // Swap or move the element at left with the element at right
        std::swap(array[left], array[right]);
        --right;  // Move the right pointer inward
    }
}
// Result depends on the final position of right
return right + 1;  // or another expression based on the problem
```

### Pattern Recognition

- **When to use:**  
  - You need to *remove* or *partition* elements based on a predicate.  
  - The removal can be achieved by moving unwanted elements to the end of the array.  
  - The array size is small enough that in‑place manipulation is acceptable.  
- **Similar problems:**  
  - *Remove Duplicates from Sorted Array II* (partitioning with two pointers).  
  - *Move Zeroes* (swap zeros to the end).  
  - *Remove Duplicates from Sorted Array* (two‑pointer partitioning).  

### Key Insight

By maintaining a `last` pointer that always points to the last *valid* position, we can **swap** any unwanted element found at the front with the element at `last`.  
After the swap, `last` moves left, shrinking the effective array.  
The invariant is: **all elements after `last` are already removed or will never be examined again**.  
This guarantees that the algorithm runs in linear time and constant space.
