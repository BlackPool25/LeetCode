## 1. Problem Statement

> Given a sorted array of **distinct** integers and a target value, return the index if the target is found. If not, return the index where it would be if it were inserted in order.  
>  
> **Example 1:**  
> Input: `nums = [1,3,5,6]`, `target = 5`  
> Output: `2`  
> Explanation: The target is found at index 2.  
>  
> **Example 2:**  
> Input: `nums = [1,3,5,6]`, `target = 2`  
> Output: `1`  
> Explanation: The target would be inserted at index 1 to maintain sorted order.  
>  
> **Example 3:**  
> Input: `nums = [1,3,5,6]`, `target = 7`  
> Output: `4`  
> Explanation: The target would be inserted at the end of the array.

---

## 2. Constraints & Key Observations

- **Constraints:**  
    - `1 <= nums.length <= 10^4`  
    - `-10^4 <= nums[i] <= 10^4`  
    - `nums` contains **distinct** values sorted in **ascending** order.  
    - `-10^4 <= target <= 10^4`  

- **What constraints tell us:**  
    - The array is **guaranteed to be sorted** and **contains no duplicates**, which allows binary search to work correctly.  
    - The **O(log n)** runtime requirement implies a **binary search** approach is required.  

- **Key observations:**  
    - The array is sorted, so we can use **binary search** to find the target or determine the insertion point.  
    - The **insertion position** is always between the last element smaller than the target and the first element larger than the target.  

- **Edge cases to handle (based on actual constraints):**  
    - Target is **smaller than all elements** (e.g., `target = 0` in `[1,2,3]` → output `0`).  
    - Target is **larger than all elements** (e.g., `target = 10` in `[1,2,3]` → output `3`).  
    - Target is **exactly at the boundary** between two elements (e.g., `target = 3` in `[1,4,5]` → output `1`).

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Binary search can be used to find the **insertion point** even if the target is not present.  
- **Algorithm invariant:** At any point, the **`front` pointer** represents the **smallest index where the target could be inserted** if not found.  
- **Why this works:** The binary search loop narrows down the search space by comparing the middle element to the target, and the final `front` value always points to the correct insertion position.  

### 3.2 Algorithm Strategy

1. Initialize two pointers: `front = 0` and `rear = nums.size() - 1`.  
2. While `front <= rear`, compute the middle index `mid = front + (rear - front) / 2`.  
3. If `nums[mid] == target`, return `mid` immediately.  
4. If `nums[mid] < target`, move the `front` pointer to `mid + 1` (target must be in the right half).  
5. If `nums[mid] > target`, move the `rear` pointer to `mid - 1` (target must be in the left half).  
6. After the loop, return `front` as the insertion position.  

---

## 4. Example Walkthrough

**Input:** `nums = [1,3,5,6]`, `target = 2`  
**Output:** `1`  

**Initial state:**  
- `front = 0`, `rear = 3`  

**Execution trace:**  
- **Step 1:** `mid = 1` → `nums[1] = 3` > `target = 2` → `rear = 0`  
- **Step 2:** `front = 0`, `rear = 0` → `mid = 0` → `nums[0] = 1` < `target = 2` → `front = 1`  
- **Step 3:** Loop ends (`front > rear`). Return `front = 1`  

**Final result:** `1` (correct insertion position).  

---

## 5. Complexity Analysis

- **Time Complexity:** $O(\log n)$  
    - **Why:** Binary search reduces the search space by half in each iteration.  

- **Space Complexity:** $O(1)$  
    - **Why:** Only constant variables (`front`, `rear`, `mid`) are used, independent of input size.  

---

## 6. Code Solution (C++)

```cpp
class Solution {

public:

    int searchInsert(vector<int>& nums, int target) {

        int front = 0;

        int rear = nums.size()-1;

        while(front <= rear){

            int mid = front + (rear - front)/2;

            if(nums[mid] == target) return mid;

            else if(nums[mid] < target) front = mid+1;

            else rear = mid-1;

        }

        return front; // Front always holds the position where the element just greater than the target if not found

    }

};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**  
    - The input is a **sorted array** with **distinct elements**.  
    - You need to **find the insertion position** of a target in **logarithmic time**.  
    - The **binary search** approach is required to meet the $O(\log n)$ time constraint.  

- **Pattern Structure (reusable template):**  

```cpp
// Binary Search - Standard Implementation
// Find the insertion position of a target in a sorted array

int front = 0;  // Points to the left boundary of the search space
int rear = nums.size() - 1;  // Points to the right boundary of the search space

while (front <= rear) {
    int mid = front + (rear - front) / 2;
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) front = mid + 1;
    else rear = mid - 1;
}

return front;  // Insertion position if target not found
```

### 🔍 Key Takeaways

- **Binary search** is not only for finding elements but also for determining **insertion positions** in sorted arrays.  
- The **`front` pointer** always points to the **correct insertion index** if the target is not found.  
- **Common mistake:** Using `mid = (front + rear) / 2` instead of `mid = front + (rear - front) / 2` can cause integer overflow in some languages (not an issue in C++).
