

# 69. Sqrt(x)

## 0. Problem Metadata

- **Difficulty:** Easy
- **Topics/Tags:** Binary Search, Math
- **Pattern Category:** Binary Search - Classic
- **LeetCode Link:** [https://leetcode.com/problems/sqrtx/](https://leetcode.com/problems/sqrtx/)

## 1. Problem Statement

> Given a non-negative integer `x`, return the square root of `x` rounded down to the nearest integer. The returned integer should be **non-negative** as well. You **must not use** any built-in exponent function or operator.

> **Example 1:**  
> Input: `x = 4`  
> Output: `2`  
> Explanation: The square root of 4 is 2, so we return 2.

> **Example 2:**  
> Input: `x = 8`  
> Output: `2`  
> Explanation: The square root of 8 is 2.82842..., and since we round it down to the nearest integer, 2 is returned.

## 2. Constraints & Key Observations

- **Constraints:**
    - `0 <= x <= 2^31 - 1`

- **What constraints tell us:**
    - `x` can be as large as $2^{31} - 1$, which implies that any solution with $O(x)$ time complexity is infeasible
    - The solution must avoid floating-point operations entirely

- **Key observations:**
    - The square root function is **monotonic** up to the integer square root
    - The square of any number greater than the integer square root will exceed `x`
    - The solution must find the **largest integer** `n` such that $n^2 \leq x$

- **Edge cases to handle (based on actual constraints):**
    - `x = 0` → Output: `0`
    - `x = 1` → Output: `1`
    - `x = 2` → Output: `1`
    - `x = 3` → Output: `1`

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Binary search can be used to find the largest integer `n` such that $n^2 \leq x$
- **Algorithm invariant:** At any point in the binary search, the correct answer lies within the current `[front, rear]` range
- **Why this works:** The square function is monotonic up to the integer square root, making binary search a natural fit

### 3.2 Algorithm Strategy

1. Initialize search range with `front = 1` and `rear = x`
2. While `front <= rear`, compute `mid` as the midpoint of the range
3. Compare $mid^2$ with `x`:
    - If equal → return `mid`
    - If $mid^2 < x$ → search in the upper half
    - If $mid^2 > x$ → search in the lower half
4. When the loop ends, return `rear` as the largest valid integer

## 4. Example Walkthrough

**Input:** `x = 8`

**Initial state:**
- `front = 1`, `rear = 8`

**Execution trace:**

- **Step 1:** `mid = 4` → $4^2 = 16 > 8$ → `rear = 3`
- **Step 2:** `mid = 2` → $2^2 = 4 < 8$ → `front = 3`
- **Step 3:** `mid = 3` → $3^2 = 9 > 8$ → `rear = 2`
- **Step 4:** Loop ends (`front > rear`)

**Final result:** `2`

## 5. Complexity Analysis

- **Time Complexity:** $O(\log x)$  
    - Why: Binary search reduces the search space by half in each iteration

- **Space Complexity:** $O(1)$  
    - Why: Only constant variables (`front`, `rear`, `mid`) are used

## 6. Code Solution (C++)

```cpp
class Solution {

public:

    int mySqrt(int x) {

        int front = 1;

        int rear = x;

        while(front <= rear) {

            int mid = front + (rear - front)/2;

            if(mid == x/mid) return mid;

            else if(mid < x/mid) front = mid + 1;

            else rear = mid - 1;

        }

        return rear;

    }

};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**
    - You need to find a **threshold value** in a **monotonic** function
    - The search space is **discrete** and **bounded**
    - You want to avoid **brute-force** $O(n)$ solutions

- **Pattern Structure (reusable template):**

```cpp
// Binary Search - Classic
// Find the largest integer n such that n^2 <= x

int front = 1;  // Lower bound of search space
int rear = x;  // Upper bound of search space

while(front <= rear) {
    int mid = front + (rear - front)/2;  // Avoid overflow
    if(mid == x/mid) return mid;  // Exact match
    else if(mid < x/mid) front = mid + 1;  // Search upper half
    else rear = mid - 1;  // Search lower half
}

return rear;  // Final answer after loop
```

### 🔍 Key Observations

- The use of `mid = front + (rear - front)/2` avoids potential integer overflow
- The comparison `mid == x/mid` is safe because `x` is non-negative
- The final return value is `rear` because the loop ends when `front > rear`, and `rear` is the last valid value

### 📌 Edge Case Handling

- For `x = 0`, the code returns `0` (since `front = 1` and `rear = 0` → loop doesn't execute)
- For `x = 1`, the code returns `1` (since `mid = 1` and `1^2 = 1`)
