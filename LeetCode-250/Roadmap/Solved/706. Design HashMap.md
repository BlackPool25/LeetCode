## 1. Problem Statement

> Design a HashMap without using any built-in hash table libraries.

> Implement the `MyHashMap` class:

> - `MyHashMap()` initializes the object with an empty map.
> - `void put(int key, int value)` inserts a `(key, value)` pair into the HashMap. If the `key` already exists in the map, update the corresponding `value`.
> - `int get(int key)` returns the `value` to which the specified `key` is mapped, or `-1` if this map contains no mapping for the `key`.
> - `void remove(int key)` removes the `key` and its corresponding `value` if the map contains the mapping for the `key`.

**Example 1:**

**Input**  
["MyHashMap", "put", "put", "get", "get", "put", "get", "remove", "get"]  
[[], [1, 1], [2, 2], [1], [3], [2, 1], [2], [2], [2]]  

**Output**  
[null, null, null, 1, -1, null, 1, null, -1]  

**Explanation**  
MyHashMap myHashMap = new MyHashMap();  
myHashMap.put(1, 1); // The map is now [[1,1]]  
myHashMap.put(2, 2); // The map is now [[1,1], [2,2]]  
myHashMap.get(1);    // return 1, The map is now [[1,1], [2,2]]  
myHashMap.get(3);    // return -1 (i.e., not found), The map is now [[1,1], [2,2]]  
myHashMap.put(2, 1); // The map is now [[1,1], [2,1]] (i.e., update the existing value)  
myHashMap.get(2);    // return 1, The map is now [[1,1], [2,1]]  
myHashMap.remove(2); // remove the mapping for 2, The map is now [[1,1]]  
myHashMap.get(2);    // return -1 (i.e., not found), The map is now [[1,1]]  

**Example 2:**  
**Input**  
["MyHashMap", "put", "get", "put", "get", "remove", "get"]  
[[], [1, 1], [1], [1, 2], [1], [1], [1]]  

**Output**  
[null, null, 1, null, 2, null, -1]

## 2. Constraints & Key Observations

- **Constraints:**
    - `0 <= key, value <= 10^6`
    - At most `10^4` calls will be made to `put`, `get`, and `remove`.

- **What constraints tell us:**
    - `10^4` operations suggest that O(1) average-case time per operation is acceptable.
    - Key range up to `10^6` implies that a naive array of size `10^6` is not memory-efficient.

- **Key observations:**
    - A custom hash function is used to map keys to a smaller range (1009 buckets).
    - Collision resolution is handled via **chaining** (using `vector<pair<int, int>>` for each bucket).
    - The hash function is designed to reduce collisions and distribute keys evenly.

- **Edge cases to handle (based on actual constraints):**
    - Keys that hash to the same bucket (collision).
    - Multiple updates to the same key.
    - Removal of a key that does not exist in the bucket.

---

## 3. Core Intuition

The solution uses **separate chaining** (a vector of vectors) to manage collisions. Each bucket (indexed by the hash function) contains a list of key-value pairs. This allows efficient insertion, retrieval, and deletion in average O(1) time.

The custom hash function is crucial for distributing keys evenly across the buckets, which minimizes collisions and ensures good performance.

---

## 4. Algorithm Strategy

1. **Hashing:** Compute the hash of the key using a custom function and modulo the table size to determine the bucket index.
2. **Collision Handling:** Use a vector of pairs in each bucket to store multiple entries that hash to the same index.
3. **Operations:**
    - **Put:** Search the bucket for the key. If found, update the value; otherwise, append a new pair.
    - **Get:** Search the bucket for the key and return the value if found.
    - **Remove:** Use `remove_if` to find and erase the key from the bucket.

## 5. Example Walkthrough

**Scenario:**  
`put(1, 1)`  
- Compute hash of `1` → `index = hash(1) % 1009`  
- Check bucket at `index`. If no entry with key `1`, append `(1, 1)`.

**Scenario:**  
`put(1, 2)`  
- Compute hash of `1` → same `index`  
- Find `(1, 1)` in the bucket and update to `(1, 2)`.

**Scenario:**  
`remove(1)`  
- Compute hash of `1` → same `index`  
- Use `remove_if` to find and erase the entry with key `1`.

## 6. Complexity Analysis

- **Time Complexity:**
    - **Average Case:** $O(1)$ for `put`, `get`, and `remove` (assuming uniform hash distribution).
    - **Worst Case:** $O(n)$ if all keys hash to the same bucket (e.g., poor hash function).
- **Space Complexity:** $O(n)$, where $n$ is the number of key-value pairs stored.

## 7. Code Implementation

```cpp
class MyHashMap {
public:
    int size = 1009;
    vector<vector<pair<int, int>>> table;

    MyHashMap() {
        table.resize(size);
    }

    int hash(int key) {
        int h = key;
        h = ((h >> 16) ^ h) * 0x45d9f3b;
        h = ((h >> 16) ^ h) * 0x45d9f3b;
        h = (h >> 16) ^ h;
        return h & 0x7FFFFFFF;
    }

    void put(int key, int value) {
        int index = hash(key) % size;

        for (auto& item : table[index]) {
            if (item.first == key) {
                item.second = value;
                return;
            }
        }
        table[index].emplace_back(key, value);
    }

    int get(int key) {
        int index = hash(key) % size;

        for (auto& item : table[index]) {
            if (item.first == key) {
                return item.second;
            }
        }
        return -1;
    }

    void remove(int key) {
        int index = hash(key) % size;

        auto& bucket = table[index];
        auto it = remove_if(bucket.begin(), bucket.end(), [key](const pair<int, int>& element) {
            return element.first == key;
        });

        bucket.erase(it, bucket.end());
    }
};
```

## 8. Key Takeaways

- **Pattern Recognition:**  
  This approach is ideal for scenarios requiring a custom hash table with collision resolution via chaining. Similar problems include:
  - **LC 705. Design HashSet** (uses chaining with a single value per bucket).
  - **LC 146. LRU Cache** (combines a hash map with a doubly linked list for eviction).

- **Reusable Framework:**  
  ```cpp
  class CustomHashMap {
  private:
      int tableSize;
      vector<vector<pair<int, int>>> buckets;

  public:
      CustomHashMap(int size) : tableSize(size), buckets(size) {}

      int hash(int key) { /* custom hash function */ }

      void put(int key, int value) {
          int index = hash(key) % tableSize;
          for (auto& item : buckets[index]) {
              if (item.first == key) {
                  item.second = value;
                  return;
              }
          }
          buckets[index].emplace_back(key, value);
      }

      int get(int key) {
          int index = hash(key) % tableSize;
          for (auto& item : buckets[index]) {
              if (item.first == key) {
                  return item.second;
              }
          }
          return -1;
      }

      void remove(int key) {
          int index = hash(key) % tableSize;
          auto& bucket = buckets[index];
          auto it = remove_if(bucket.begin(), bucket.end(), [key](const pair<int, int>& element) {
              return element.first == key;
          });
          bucket.erase(it, bucket.end());
      }
  };
  ```

- **Common Mistakes to Avoid:**
  - Not using a good hash function (leading to poor performance).
  - Failing to handle collisions (e.g., using open addressing instead of chaining).
  - Incorrectly implementing `remove` (e.g., not using `remove_if` or `erase` properly).
