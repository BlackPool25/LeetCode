

# 206. Reverse Linked List

## 1. Problem Statement

> Given the `head` of a singly linked list, reverse the list, and return the reversed list.

**Example 1:**  
Input: `head = [1,2,3,4,5]`  
Output: `[5,4,3,2,1]`  
Explanation: The linked list is reversed in-place, with the last node becoming the new head.

**Example 2:**  
Input: `head = [1,2]`  
Output: `[2,1]`  
Explanation: The two-node list is reversed.

**Example 3:**  
Input: `head = []`  
Output: `[]`  
Explanation: An empty list returns itself.

    - Reversal can be done iteratively with constant space.
    - The reversal process involves updating the `next` pointers of each node.

- **Edge cases to handle (based on actual constraints):**
    - Empty list (`head = nullptr`): return `nullptr`.
    - Single-node list: return the same node.
    - Two-node list: swap the two nodes.

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Reversing a linked list iteratively requires updating the `next` pointer of each node to point to its previous node.
- **Algorithm invariant:** At any point in the loop, the nodes processed so far are reversed, and the current node is being processed.
- **Why this works:** By maintaining a `prev` pointer to the last processed node and a `cur` pointer to the current node, we can iteratively reverse the list in-place with constant space.

### 3.2 Algorithm Strategy

1. Initialize `prev` to `nullptr` (the new tail of the reversed list).
2. Initialize `cur` to `head` (the current node being processed).
3. Iterate while `cur` is not `nullptr`:
    - Store the next node (`temp`) to avoid losing the reference.
    - Update `cur->next` to point to `prev`.
    - Move `prev` forward to `cur`.
    - Move `cur` forward to `temp`.
4. After the loop, `prev` will point to the new head of the reversed list.

## 4. Example Walkthrough

**Input:** `head = [1,2,3,4,5]`

**Initial state:**
- `prev = nullptr`
- `cur = 1`

**Execution trace:**

- **Step 1:**  
  `cur = 1`, `temp = 2`  
  `cur->next = prev (nullptr)`  
  `prev = 1`, `cur = 2`

- **Step 2:**  
  `cur = 2`, `temp = 3`  
  `cur->next = prev (1)`  
  `prev = 2`, `cur = 3`

- **Step 3:**  
  `cur = 3`, `temp = 4`  
  `cur->next = prev (2)`  
  `prev = 3`, `cur = 4`

- **Step 4:**  
  `cur = 4`, `temp = 5`  
  `cur->next = prev (3)`  
  `prev = 4`, `cur = 5`

- **Step 5:**  
  `cur = 5`, `temp = nullptr`  
  `cur->next = prev (4)`  
  `prev = 5`, `cur = nullptr`

**Final result:** `prev = 5` (new head of the reversed list)

## 5. Complexity Analysis

- **Time Complexity:** $O(n)$  
    - Why: A single pass through the list with constant work per node.

- **Space Complexity:** $O(1)$  
    - Why: Only three pointers (`prev`, `cur`, `temp`) are used, regardless of input size.

---

## 6. Code Solution (C++)

```cpp
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        ListNode *prev = NULL;
        ListNode *cur = head;
        
        while (cur != NULL) {
            ListNode *temp = cur->next;
            cur->next = prev;
            prev = cur;
            cur = temp;
        }
        return prev;
    }
};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**
    - You need to reverse a singly linked list **in-place**.
    - You want to use **constant space** and **iterative logic**.
    - The list is **not guaranteed to be sorted** or have any special structure.

- **Pattern Structure (reusable template):**

```cpp
// "Pointer Manipulation - In-Place Reversal"
// Reverses a singly linked list by updating next pointers iteratively

ListNode *prev = nullptr;  // Tracks the last processed node
ListNode *cur = head;      // Tracks the current node being processed

while (cur != nullptr) {
    ListNode *temp = cur->next;  // Save the next node
    cur->next = prev;            // Point current node to previous
    prev = cur;                  // Move previous forward
    cur = temp;                  // Move current forward
}

return prev;  // prev is the new head of the reversed list
```

### 💡 Key Insights

- The `temp` pointer is crucial to avoid losing the reference to the next node.
- The algorithm works for all edge cases (empty list, single node, multiple nodes).
- This is the **standard iterative approach** for reversing a linked list.

### 🔍 Common Mistakes

- Forgetting to update `temp` before changing `cur->next`.
- Not initializing `prev` to `nullptr` (which would cause a crash in the first iteration).
- Returning `cur` instead of `prev` at the end (which would return `nullptr` for non-empty lists).
