## 1. Problem Statement

> You are keeping the scores for a baseball game with strange rules. At the beginning of the game, you start with an empty record.
>
> You are given a list of strings `operations`, where `operations[i]` is the `ith` operation you must apply to the record and is one of the following:
>
> - An integer `x`.  
>     - Record a new score of `x`.  
> - `'+'`.  
>     - Record a new score that is the sum of the previous two scores.  
> - `'D'`.  
>     - Record a new score that is the double of the previous score.  
> - `'C'`.  
>     - Invalidate the previous score, removing it from the record.  
>
> Return the sum of all the scores on the record after applying all the operations.
>
> The test cases are generated such that the answer and all intermediate calculations fit in a **32-bit** integer and that all operations are valid.
>
> **Example 1:**  
> Input: `ops = ["5","2","C","D","+"]`  
> Output: `30`  
> Explanation:  
> "5" - Add 5 to the record, record is now `[5]`.  
> "2" - Add 2 to the record, record is now `[5, 2]`.  
> "C" - Invalidate and remove the previous score, record is now `[5]`.  
> "D" - Add 2 * 5 = 10 to the record, record is now `[5, 10]`.  
> "+" - Add 5 + 10 = 15 to the record, record is now `[5, 10, 15]`.  
> The total sum is 5 + 10 + 15 = 30.
>
> **Example 2:**  
> Input: `ops = ["5","-2","4","C","D","9","+","+"]`  
> Output: `27`  
> Explanation:  
> "5" - Add 5 to the record, record is now `[5]`.  
> "-2" - Add -2 to the record, record is now `[5, -2]`.  
> "4" - Add 4 to the record, record is now `[5, -2, 4]`.  
> "C" - Invalidate and remove the previous score, record is now `[5, -2]`.  
> "D" - Add 2 * -2 = -4 to the record, record is now `[5, -2, -4]`.  
> "9" - Add 9 to the record, record is now `[5, -2, -4, 9]`.  
> "+" - Add -4 + 9 = 5 to the record, record is now `[5, -2, -4, 9, 5]`.  
> "+" - Add 9 + 5 = 14 to the record, record is now `[5, -2, -4, 9, 5, 14]`.  
> The total sum is 5 + -2 + -4 + 9 + 5 + 14 = 27.
>
> **Example 3:**  
> Input: `ops = ["1","C"]`  
> Output: `0`  
> Explanation:  
> "1" - Add 1 to the record, record is now `[1]`.  
> "C" - Invalidate and remove the previous score, record is now `[]`.  
> Since the record is empty, the total sum is 0.

## 2. Constraints & Key Observations

- **Constraints:**  
  - `1 <= operations.length <= 1000`  
  - `operations[i]` is `"C"`, `"D"`, `"+"`, or a string representing an integer in the range `[-3 * 10^4, 3 * 10^4]`.  
  - For `"+"`, there will always be at least two previous scores on the record.  
  - For `"C"` and `"D"`, there will always be at least one previous score on the record.  

- **Key Observations:**  
  - The stack is used to maintain the current state of the record.  
  - Each operation modifies the stack in a specific way:  
    - `"+"` adds the sum of the top two elements.  
    - `"D"` doubles the top element.  
    - `"C"` removes the top element.  
    - A number is pushed directly onto the stack.  
  - The final sum is computed by summing all elements in the stack.

---

## 3. Core Intuition

- **Key Insight:**  
  Use a stack to maintain the record of scores, as it naturally supports LIFO (Last-In-First-Out) operations, which are required for operations like `"C"` (remove last) and `"D"` (double last).  

- **Invariant:**  
  The stack always reflects the current state of the record after each operation.  

- **Why Stack?**  
  The stack allows efficient access to the most recent elements, which is essential for operations like `"+"` (sum of last two) and `"D"` (double last). It also simplifies the `"C"` operation by allowing direct removal of the top element.

---

## 4. Algorithm Strategy

1. Initialize an empty stack to store the scores.  
2. Iterate through each operation in the input list:  
   - If the operation is `"+"`:  
     - Pop the top two elements, add them, and push the result back onto the stack.  
   - If the operation is `"D"`:  
     - Pop the top element, double it, and push the result back onto the stack.  
   - If the operation is `"C"`:  
     - Pop the top element (discard it).  
   - If the operation is a number:  
     - Convert it to an integer and push it onto the stack.  
3. After processing all operations, compute the sum of all elements in the stack by popping them one by one.  
4. Return the computed sum.

## 5. Example Walkthrough

**Example 1:**  
Input: `["5", "2", "C", "D", "+"]`  
- `"5"` → Stack: `[5]`  
- `"2"` → Stack: `[5, 2]`  
- `"C"` → Stack: `[5]`  
- `"D"` → Stack: `[5, 10]`  
- `"+"` → Stack: `[5, 10, 15]`  
- Sum: `5 + 10 + 15 = 30`

## 6. Complexity Analysis

- **Time Complexity:** $O(n)$, where $n$ is the number of operations. Each operation is processed in constant time.  
- **Space Complexity:** $O(n)$, as the stack can grow to the size of the input list in the worst case.

## 7. Code Solution

```cpp
class Solution {
public:
    int calPoints(vector<string>& operations) {
        stack<int> myStack;

        for (int i = 0; i < operations.size(); i++) {
            if (operations[i] == "+") {
                int num2 = myStack.top();
                myStack.pop();
                int num1 = myStack.top();
                myStack.push(num2);
                myStack.push(num1 + num2);
            } else if (operations[i] == "D") {
                int num = myStack.top();
                myStack.push(num * 2);
            } else if (operations[i] == "C") {
                myStack.pop();
            } else {
                int num = stoi(operations[i]);
                myStack.push(num);
            }
        }

        int sum = 0;
        while (!myStack.empty()) {
            sum += myStack.top();
            myStack.pop();
        }

        return sum;
    }
};
```

- **Reusable Structure:**  
  This pattern is useful in problems where a stack is used to maintain a dynamic list of elements that require conditional modification (e.g., removing the last element, doubling it, or summing the last two).

## 9. Key Takeaways

- **When to Use This Pattern:**  
  When you need to maintain a dynamic list of elements with LIFO behavior and perform conditional operations on the most recent elements (e.g., "undo" operations, "double" operations, or "sum" operations).

- **Common Mistakes to Avoid:**  
  - Incorrect order when handling `"+"` (e.g., popping the wrong element first).  
  - Forgetting to push the popped element back onto the stack after processing `"+"`.  
  - Not handling `"C"` correctly (e.g., not popping the top element).  

- **Edge Cases to Consider:**  
  - Empty stack after `"C"` operations.  
  - All operations being `"C"` (resulting in an empty stack).  
  - All operations being numbers (no `"+"`, `"D"`, or `"C"`).
