

# 1. Two Sum

## 0. Problem Metadata

- **Difficulty:** Easy
- **Topics/Tags:** Array, Hash Table, Two Pointers (conceptual), Hash Map
- **Pattern Category:** **Hash Map – Complement Search (Single Pass)**
- **LeetCode Link:** https://leetcode.com/problems/two-sum/

## 1. Problem Statement

> **Given an array of integers `nums` and an integer `target`, return the indices of the two numbers such that they add up to `target`.**  
> You may assume that each input would have **exactly one solution**, and you may not use the same element twice.  
> You can return the answer in any order.  
> 
> **Example 1:**  
> **Input:** `nums = [2,7,11,15]`, `target = 9`  
> **Output:** `[0,1]`  
> **Explanation:** Because `nums[0] + nums[1] == 9`, we return `[0, 1]`.  
> 
> **Example 2:**  
> **Input:** `nums = [3,2,4]`, `target = 6`  
> **Output:** `[1,2]`  
> 
> **Example 3:**  
> **Input:** `nums = [3,3]`, `target = 6`  
> **Output:** `[0,1]`  
> 
> **Constraints:**  
> - `2 <= nums.length <= 10^4`  
> - `-10^9 <= nums[i] <= 10^9`  
> - `-10^9 <= target <= 10^9`  
> - **Only one valid answer exists.**  
> 
> **Follow-up:** Can you come up with an algorithm that is less than `O(n^2)` time complexity?

## 2. Constraints & Key Observations

- **Constraints:**
  - `2 ≤ nums.length ≤ 10^4`
  - `-10^9 ≤ nums[i] ≤ 10^9`
  - `-10^9 ≤ target ≤ 10^9`
  - Exactly one solution is guaranteed.
- **What constraints tell us:**
  - `n` can be up to `10^4`; an `O(n^2)` solution would perform up to ~10⁸ operations, which is borderline or too slow.  
  - We can afford an `O(n)` algorithm with `O(n)` auxiliary space.
- **Key observations:**
  - For each element `x`, we need to know if `target - x` has appeared earlier.  
  - The array may contain negative numbers and duplicates; the algorithm must handle both.
- **Edge cases to handle (based on actual constraints):**
  - Two identical numbers that sum to the target (e.g., `[3,3]` with target `6`).  
  - The target is zero and the array contains `0` twice.  
  - The array contains the target value itself but not as a pair (must not use the same index twice).

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:**  
  If we know the value of `target - nums[i]` (the *complement*), we can instantly find the pair by looking it up in a hash map.  
- **Algorithm invariant:**  
  At any iteration `i`, the hash map contains all numbers from indices `< i` and their corresponding indices.  
- **Why it works:**  
  When we encounter `nums[i]`, if its complement is already in the map, the two indices form the required sum.  
  Otherwise, we store `nums[i]` for future complement checks.

### 3.2 Algorithm Strategy

1. Create an empty hash map `mydic` mapping number → index.  
2. Iterate over `nums` with index `i`.  
3. Compute `diff = target - nums[i]`.  
4. If `diff` exists in `mydic`, return `[i, mydic[diff]]`.  
5. Otherwise, insert `nums[i] → i` into `mydic`.  
6. Continue until the pair is found (guaranteed by constraints).

### 3.3 Example Walkthrough (Example 1)

| Step | `i` | `nums[i]` | `diff = target - nums[i]` | `mydic` before lookup | Action | `mydic` after |
|------|-----|-----------|---------------------------|-----------------------|--------|---------------|
| 1    | 0   | 2         | 7                         | `{}`                  | Insert `2 → 0` | `{2:0}` |
| 2    | 1   | 7         | 2                         | `{2:0}`               | Found → return `[1,0]` (or `[0,1]`) | — |

**Final result:** `[0,1]` (order may vary).

### 3.4 Template / Reusable Structure

```cpp
unordered_map<int, int> map;          // Store value → index
for (int i = 0; i < nums.size(); ++i) {
    int complement = target - nums[i];
    if (map.count(complement)) {
        return {i, map[complement]}; // Found the pair
    }
    map[nums[i]] = i;                 // Record current value
}
```

## 4. Complexity Analysis

- **Time complexity:** $O(n)$ – each element is processed once and hash‑map operations are $O(1)$ on average.  
- **Space complexity:** $O(n)$ – in the worst case we store all elements in the hash map.

## 5. Code Solution

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> mydic; // Hash map to store number and its index
        for(int i = 0; i < nums.size(); i++) {
            int diff = target - nums[i]; // Calculate the complement
            if(mydic.count(diff)) { // Complement already seen?
                return vector<int>{i, mydic[diff]}; // Return current index and stored index
            } else {
                mydic[nums[i]] = i; // Store current number for future complements
            }
        }
        return {}; // Should never reach here because a solution is guaranteed
    }
};
```

## 5. Key Takeaways / Patterns

- **Hash Map Usage:**  
  A hash map allows constant‑time lookups for the required complement, turning a quadratic problem into linear time.  
- **Single‑Pass Strategy:**  
  By building the map on the fly, we avoid a second pass or nested loops.  
- **Handling Duplicates:**  
  The algorithm naturally handles cases where the same value appears twice because the map stores indices of *previous* occurrences only.

## 6. Key Takeaways / Patterns

- **Hash Map – Complement Search** is the canonical solution for any problem that asks for two elements summing to a given value.  
- **Reusable template** (see above) can be applied to variations such as:
  - *Three Sum* (use a nested loop + hash map for the remaining two).  
  - *Two Sum II – Input array is sorted* (use two‑pointer technique instead of hash map).  
  - *Four Sum* (extend the idea to pairs of pairs).  

## 7. Key Takeaways / Patterns

- **Hash Map Usage:**  
  Utilizing a hash map for quick lookups and insertions can significantly reduce time complexity.  
- **Single Pass Algorithm:**  
  The problem can often be solved in linear time by using additional data structures like hash maps or sets.  
- **Edge Case Handling:**  
  Always consider edge cases, such as the possibility of duplicate elements or constraints on input size.
