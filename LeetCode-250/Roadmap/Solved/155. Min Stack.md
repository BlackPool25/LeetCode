

# 155. Min Stack

## 0. Problem Metadata

- **Difficulty:** Medium  
- **Topics/Tags:** Stack, Design  
- **Pattern Category:** Stack - Augmented Data Structure  
- **LeetCode Link:** [https://leetcode.com/problems/min-stack/](https://leetcode.com/problems/min-stack/)

## 1. Problem Statement

> Design a stack that supports push, pop, top, and retrieving the minimum element in constant time.
>
> Implement the `MinStack` class:
>
> - `MinStack()` initializes the stack object.
> - `void push(int val)` pushes the element `val` onto the stack.
> - `void pop()` removes the element on the top of the stack.
> - `int top()` gets the top element of the stack.
> - `int getMin()` retrieves the minimum element in the stack.
>
> You must implement a solution with `O(1)` time complexity for each function.
>
> **Example 1:**
>
> **Input**  
> `["MinStack","push","push","push","getMin","pop","top","getMin"]`  
> `[[],[-2],[0],[-3],[],[],[],[]]`
>
> **Output**  
> `[null,null,null,null,-3,null,0,-2]`
>
> **Explanation**  
> `MinStack minStack = new MinStack();`  
> `minStack.push(-2);`  
> `minStack.push(0);`  
> `minStack.push(-3);`  
> `minStack.getMin(); // return -3`  
> `minStack.pop();`  
> `minStack.top();    // return 0`  
> `minStack.getMin(); // return -2`

## 2. Constraints & Key Observations

- **Constraints:**
    - `-2^31 <= val <= 2^31 - 1`
    - Methods `pop`, `top`, and `getMin` will always be called on **non-empty** stacks.
    - At most `3 * 10^4` calls will be made to `push`, `pop`, `top`, and `getMin`.

- **What constraints tell us:**
    - No need to handle empty stack cases for `pop`, `top`, or `getMin`.
    - Input size is manageable with `O(1)` per-operation algorithms.

- **Key observations:**
    - Each element must carry the **minimum value up to that point** in the stack.
    - The minimum can only change when a new element is pushed or the current minimum is popped.

- **Edge cases to handle (based on actual constraints):**
    - Single-element stack (e.g., after a `push` and `pop`).
    - Stack with all elements equal (e.g., `[5,5,5]`).
    - Stack with increasing values (e.g., `[1,2,3]`).

---

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Store the **current minimum** with each element in the stack.
- **Algorithm invariant:** Every element in the stack is a pair `(value, current_min)`, where `current_min` is the minimum value from the bottom of the stack up to that element.
- **Why this works:** By storing the minimum with each element, `getMin()` can be answered in `O(1)` time by simply reading the second value of the top pair.

### 3.2 Algorithm Strategy

1. **Initialize a stack** that stores pairs of `(value, current_min)`.
2. **For `push(val)`:**
    - If the stack is empty, push `(val, val)`.
    - Otherwise, compute the new current minimum as `min(val, previous_min)` and push `(val, new_min)`.
3. **For `pop()`:** Remove the top element from the stack.
4. **For `top()`:** Return the first value of the top pair.
5. **For `getMin()`:** Return the second value of the top pair.

## 4. Example Walkthrough

**Input:**  
`["MinStack","push","push","push","getMin","pop","top","getMin"]`  
`[[],[-2],[0],[-3],[],[],[],[]]`

**Initial state:**  
`myStack = empty`

**Execution trace:**

- **Step 1:** `push(-2)`  
  - Stack is empty → push `(-2, -2)`  
  - `myStack = [(-2, -2)]`

- **Step 2:** `push(0)`  
  - Previous min is `-2` → new min is `min(0, -2) = -2`  
  - Push `(0, -2)`  
  - `myStack = [(-2, -2), (0, -2)]`

- **Step 3:** `push(-3)`  
  - Previous min is `-2` → new min is `min(-3, -2) = -3`  
  - Push `(-3, -3)`  
  - `myStack = [(-2, -2), (0, -2), (-3, -3)]`

- **Step 4:** `getMin()`  
  - Return `myStack.top().second = -3`

- **Step 5:** `pop()`  
  - Remove `(-3, -3)`  
  - `myStack = [(-2, -2), (0, -2)]`

- **Step 6:** `top()`  
  - Return `myStack.top().first = 0`

- **Step 7:** `getMin()`  
  - Return `myStack.top().second = -2`

**Final result:** `[null,null,null,null,-3,null,0,-2]`

## 5. Complexity Analysis

- **Time Complexity:** $O(1)$  
    - **Why:** All operations (`push`, `pop`, `top`, `getMin`) involve only constant-time operations on the stack.

- **Space Complexity:** $O(n)$  
    - **Why:** The stack stores $n$ pairs, where $n$ is the number of elements pushed.

## 6. Code

```cpp
class MinStack {
public:
    stack<pair<int, int>> myStack;

    MinStack() {}

    void push(int val) {
        if (myStack.empty()) {
            myStack.push({val, val});
        } else {
            myStack.push({val, min(val, myStack.top().second)});
        }
    }

    void pop() {
        myStack.pop();
    }

    int top() {
        return myStack.top().first;
    }

    int getMin() {
        return myStack.top().second;
    }
};
```

## 7. Key Takeaways

### **Pattern Recognition**

- **When to use this pattern:**  
  When you need to **track additional information** (like the current minimum) with each element in a stack, and all operations must be `O(1)`.

- **Reusable structure:**  
  ```cpp
  stack<pair<int, int>> myStack;
  push(val) {
      if (empty) {
          push({val, val});
      } else {
          push({val, min(val, myStack.top().second)});
      }
  }
  ```
