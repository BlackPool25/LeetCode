

# 20. Valid Parentheses

## 1. Problem Statement

> Given a string `s` containing just the characters `'('`, `')'`, `'{'`, `'}'`, `'['` and `']'`, determine if the input string is valid.

> An input string is valid if:
> 
> 1. Open brackets must be closed by the same type of brackets.
> 2. Open brackets must be closed in the correct order.
> 3. Every close bracket has a corresponding open bracket of the same type.

> **Example 1:**  
> Input: `s = "()"`  
> Output: `true`  
> Explanation: The brackets are properly closed in the correct order.

> **Example 2:**  
> Input: `s = "()[]{}"`  
> Output: `true`  
> Explanation: All brackets are properly closed in the correct order.

> **Example 3:**  
> Input: `s = "(]"`  
> Output: `false`  
> Explanation: The closing bracket `']'` does not match the most recent open bracket `'('`.

> **Example 4:**  
> Input: `s = "([])"`  
> Output: `true`  
> Explanation: Nested brackets are properly closed in the correct order.

> **Example 5:**  
> Input: `s = "([)]"`  
> Output: `false`  
> Explanation: The closing bracket `')'` does not match the most recent open bracket `'['`.

---

## 2. Constraints & Key Observations

- **Constraints:**
    - `1 <= s.length <= 10^4`
    - `s` consists of parentheses only: `'()[]{}'`

- **What constraints tell us:**
    - Input size is up to 10,000 characters, so O(n) algorithms are acceptable.
    - No need to handle empty strings or non-parentheses characters.

- **Key observations:**
    - The problem requires **matching pairs** in **LIFO (Last-In-First-Out)** order.
    - A **stack** is the natural data structure to enforce this order.
    - Each closing bracket must match the **most recent** unmatched opening bracket.

- **Edge cases to handle (based on actual constraints):**
    - All opening brackets (e.g., `"(((") → stack not empty at end → invalid).
    - All closing brackets (e.g., `")))"` → stack underflow during processing → invalid.
    - Nested brackets (e.g., `"([{}])"` → valid).
    - Mismatched brackets (e.g., `"([)]"` → invalid).

---

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:**  
  A stack can be used to track the order of opening brackets. When a closing bracket is encountered, it must match the most recent unmatched opening bracket (i.e., the top of the stack).

- **Algorithm invariant:**  
  At any point, the stack contains all unmatched opening brackets in the order they were encountered.

- **Why this works:**  
  The stack ensures that closing brackets are matched in the correct order. If a mismatch is found at any point, the string is invalid. At the end, the stack must be empty for the string to be valid.

---

### 3.2 Algorithm Strategy

1. Initialize an empty stack to store opening brackets.
2. Iterate through each character in the string:
    - If the character is an opening bracket (`'('`, `'{'`, `'['`), push it onto the stack.
    - If the character is a closing bracket (`')'`, `'}'`, `']'`):
        - Check if the stack is not empty and the top of the stack matches the corresponding opening bracket.
        - If it matches, pop the stack.
        - If it does not match, return `false`.
3. After processing all characters, return `true` if the stack is empty (all brackets matched), otherwise `false`.

---

## 4. Example Walkthrough

**Input:** `s = "([])"`

**Initial state:**
- Stack: `[]` (empty)

**Execution trace:**

- **Step 1:** `i = 0`, `ch = '('`  
  - Push `'('` to stack → Stack: `['(']`

- **Step 2:** `i = 1`, `ch = '['`  
  - Push `'['` to stack → Stack: `['(', '[']`

- **Step 3:** `i = 2`, `ch = ']'`  
  - Stack is not empty, and `stack.top() == '['` → Pop → Stack: `['(']`

- **Step 4:** `i = 3`, `ch = ')'`  
  - Stack is not empty, and `stack.top() == '('` → Pop → Stack: `[]`

**Final result:** Stack is empty → return `true`

## 5. Complexity Analysis

- **Time Complexity:** $O(n)$  
    - Single pass through the string (n iterations), with constant-time operations per character.

- **Space Complexity:** $O(n)$  
    - Worst-case scenario: all characters are opening brackets, so the stack grows to size $n$.

## 6. Code Solution (C++)

```cpp
class Solution {
public:
    bool isValid(string s) {
        stack<char> s1;
        for(int i=0; i<s.length() ; i++){
            char ch = s[i];
            switch(ch){
                case '{':
                case '[':
                case '(':
                    s1.push(ch);
                    break;
                case ']':
                    if(!s1.empty() && s1.top() == '[') s1.pop();
                    else return false;
                    break;
                case '}':
                    if(!s1.empty() && s1.top() == '{') s1.pop();
                    else return false;
                    break;
                case ')':
                    if(!s1.empty() && s1.top() == '(') s1.pop();
                    else return false;
                    break;
                default:
                    break;
            }
        }
        return s1.empty();
    }
};
```

## 7. Key Takeaways & Pattern Recognition

### 🎯 Pattern Recognition

- **This pattern applies when:**
    - You need to **match pairs** in **LIFO order**.
    - The input is a **sequence of nested or ordered elements**.
    - A **stack** is the natural data structure to enforce this order.

- **Pattern Structure:**
```cpp
stack<char> stack;
for (char c : s) {
    if (isOpen(c)) {
        stack.push(c);
    } else {
        if (stack.empty() || !matches(stack.top(), c)) {
            return false;
        }
        stack.pop();
    }
}
return stack.empty();
```

---

### 🔍 Key Observations

- **Stack underflow** (empty stack when a closing bracket is encountered) → invalid.
- **Mismatched brackets** (closing bracket doesn't match top of stack) → invalid.
- **Stack not empty** at end → unmatched opening brackets → invalid.

---

### 🛠️ Common Pitfalls

- Forgetting to check if the stack is empty before popping.
- Not handling all three types of brackets (`()`, `{}`, `[]`) correctly.
- Confusing the order of matching (e.g., `')'` should match `'('`, not `'{'`).
