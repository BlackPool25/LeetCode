## 1. Problem Statement

> Implement a first in first out (FIFO) queue using only two stacks. The implemented queue should support all the functions of a normal queue (`push`, `peek`, `pop`, and `empty`).

> Implement the `MyQueue` class:

> - `void push(int x)` Pushes element `x` to the back of the queue.
> - `int pop()` Removes the element from the front of the queue and returns it.
> - `int peek()` Returns the element at the front of the queue.
> - `bool empty()` Returns `true` if the queue is empty, `false` otherwise.

**Example 1:**

**Input**  
["MyQueue", "push", "push", "peek", "pop", "empty"]  
[[], [1], [2], [], [], []]  

**Output**  
[null, null, null, 1, 1, false]  

**Explanation**  
MyQueue myQueue = new MyQueue();  
myQueue.push(1); // queue is: [1]  
myQueue.push(2); // queue is: [1, 2] (leftmost is front of the queue)  
myQueue.peek(); // return 1  
myQueue.pop(); // return 1, queue is [2]  
myQueue.empty(); // return false  

**Example 2:**  
**Input**  
["MyQueue", "push", "peek", "pop", "empty"]  
[[], [3], [], [], []]  

**Output**  
[null, null, 3, 3, false]

## 2. Constraints & Key Observations

- **Constraints:**
    - `1 <= x <= 9`
    - At most `100` calls will be made to `push`, `pop`, `peek`, and `empty`.
    - All the calls to `pop` and `peek` are valid.

- **What constraints tell us:**
    - `100` operations is small enough that even $O(n)$ per operation is acceptable.
    - `pop` and `peek` are always called on non-empty queues, so no need to handle empty cases for them.

- **Key observations:**
    - A queue (FIFO) can be simulated with two stacks by reversing the order of elements when needed.
    - The `push` operation is always $O(1)$, while `pop` and `peek` are amortized $O(1)$ due to lazy transfer between stacks.

- **Edge cases to handle (based on actual constraints):**
    - Single-element queue (push once, then pop/peek).
    - Queue with all elements pushed before any pop/peek.

## 3. Solution Development

### 3.1 Core Intuition

- **The "Aha!" moment:** Use two stacks to simulate a queue by reversing the order of elements when needed.
- **Algorithm invariant:** At any time, the `popStack` contains the elements in the correct FIFO order for popping. If it's empty, we transfer all elements from `pushStack` to `popStack` (reversing their order).
- **Why this works:** By transferring elements only when necessary, we avoid redundant operations and maintain amortized $O(1)$ time complexity for all operations.

### 3.2 Algorithm Strategy

1. **Push:** Add the element to `pushStack` (always $O(1)$).
2. **Pop/Peek:** If `popStack` is empty, transfer all elements from `pushStack` to `popStack` (reversing order), then perform the operation on `popStack`.
3. **Empty:** Check if both stacks are empty.

## 4. Example Walkthrough

**Input:**  
["MyQueue", "push", "push", "peek", "pop", "empty"]  
[[], [1], [2], [], [], []]  

**Initial state:**
- `pushStack`: empty  
- `popStack`: empty  

**Execution trace:**

- **Step 1:** `push(1)`  
  - `pushStack`: [1]  
  - `popStack`: empty  

- **Step 2:** `push(2)`  
  - `pushStack`: [1, 2]  
  - `popStack`: empty  

- **Step 3:** `peek()`  
  - `popStack` is empty → transfer all from `pushStack` to `popStack`:  
    - `pushStack`: empty  
    - `popStack`: [2, 1]  
  - Return `popStack.top()` → `1`  

- **Step 4:** `pop()`  
  - `popStack` is not empty → pop `1`  
  - `popStack`: [2]  
  - Return `1`  

- **Step 5:** `empty()`  
  - `pushStack` is empty, `popStack` is not → return `false`

## 5. Complexity Analysis

- **Time Complexity:**  
  - `push`: $O(1)$  
  - `pop`/`peek`: **Amortized $O(1)$** (each element is pushed and popped at most twice)  
- **Space Complexity:** $O(n)$ (all elements are stored in the two stacks)

## 6. Code Implementation

```cpp
class MyQueue {
public:
    stack<int> pushStack;
    stack<int> popStack;

    void push(int x) {
        pushStack.push(x);
    }

    int pop() {
        if (popStack.empty()) {
            while (!pushStack.empty()) {
                int toPush = pushStack.top();
                pushStack.pop();
                popStack.push(toPush);
            }
        }
        int toReturn = popStack.top();
        popStack.pop();
        return toReturn;
    }

    int peek() {
        if (popStack.empty()) {
            while (!pushStack.empty()) {
                int toPush = pushStack.top();
                pushStack.pop();
                popStack.push(toPush);
            }
        }
        return popStack.top();
    }

    bool empty() {
        return popStack.empty() && pushStack.empty();
    }
};
```

## 7. Key Takeaways

### **Pattern Recognition**

- **Two Stacks - Reversal for FIFO**  
  - Use two stacks to simulate a queue by transferring elements from one stack to the other when needed.
  - This pattern is useful for implementing FIFO behavior with LIFO structures.

### **Framework/Template**

```cpp
class MyQueue {
public:
    stack<int> pushStack;
    stack<int> popStack;

    void push(int x) {
        pushStack.push(x);
    }

    int pop() {
        if (popStack.empty()) {
            while (!pushStack.empty()) {
                int toPush = pushStack.top();
                pushStack.pop();
                popStack.push(toPush);
            }
        }
        int toReturn = popStack.top();
        popStack.pop();
        return toReturn;
    }

    int peek() {
        if (popStack.empty()) {
            while (!pushStack.empty()) {
                int toPush = pushStack.top();
                pushStack.pop();
                popStack.push(toPush);
            }
        }
        return popStack.top();
    }

    bool empty() {
        return popStack.empty() && pushStack.empty();
    }
};
```

### **Common Pitfalls**

- **Forgetting to transfer elements** when `popStack` is empty.
- **Not understanding amortized time complexity** and assuming `pop` is always $O(n)$.
- **Misusing stack operations** (e.g., using `pop` instead of `top` for peeking).
