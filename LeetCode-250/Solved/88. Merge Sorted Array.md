

# 88. Merge Sorted Array

## 0. Problem Metadata

- **Difficulty:** Medium
- **Topics/Tags:** Array, Two Pointers
- **Pattern Category:** Two Pointers – Reverse Merge (Backwards)
- **LeetCode Link:** https://leetcode.com/problems/merge-sorted-array/

## 1. Problem Statement

> You are given two integer arrays `nums1` and `nums2`, sorted in **non‑decreasing order**, and two integers `m` and `n`, representing the number of elements in `nums1` and `nums2` respectively.  
> 
> Merge `nums1` and `nums2` into a single array sorted in **non‑decreasing order**.  
> 
> The final sorted array should not be returned by the function, but instead be stored inside the array `nums1`. To accommodate this, `nums1` has a length of `m + n`, where the first `m` elements denote the elements that should be merged, and the last `n` elements are set to `0` and should be ignored. `nums2` has a length of `n`.  
> 
> **Example 1:**  
> 
> **Input:** `nums1 = [1,2,3,0,0,0]`, `m = 3`, `nums2 = [2,5,6]`, `n = 3`  
> 
> **Output:** `[1,2,2,3,5,6]`  
> 
> **Explanation:** The arrays we are merging are `[1,2,3]` and `[2,5,6]`. The result of the merge is `[1,2,2,3,5,6]` with the underlined elements coming from `nums1`.  
> 
> **Example 2:**  
> 
> **Input:** `nums1 = [1]`, `m = 1`, `nums2 = []`, `n = 0`  
> 
> **Output:** `[1]`  
> 
> **Explanation:** The arrays we are merging are `[1]` and `[]`. The result of the merge is `[1]`.  
> 
> **Example 3:**  
> 
> **Input:** `nums1 = [0]`, `m = 0`, `nums2 = [1]`, `n = 1`  
> 
> **Output:** `[1]`  
> 
> **Explanation:** The arrays we are merging are `[]` and `[1]`. The result of the merge is `[1]`. Note that because `m = 0`, there are no elements in `nums1`. The `0` is only there to ensure the merge result can fit in `nums1`.  
> 
> **Constraints:**  
> 
> - `nums1.length == m + n`  
> 
> - `nums2.length == n`  
> 
> - `0 <= m, n <= 200`  
> 
> - `1 <= m + n <= 200`  
> 
> - `-10^9 <= nums1[i], nums2[j] <= 10^9`  
> 
> **Follow up:** Can you come up with an algorithm that runs in `O(m + n)` time?

## 2. Constraints & Key Observations

### Constraints

| Constraint | Value |
|------------|-------|
| `nums1.length == m + n` | The buffer in `nums1` is exactly large enough for the merged result. |
| `nums2.length == n` | `nums2` contains exactly `n` elements. |
| `0 <= m, n <= 200` | Both arrays are small; an `O(m+n)` algorithm is easily fast enough. |
| `1 <= m + n <= 200` | Total number of elements is at most `200`. |
| `-10^9 <= nums1[i], nums2[j] <= 10^9` | Elements can be negative or positive; only the relative order matters. |

### What the constraints tell us

- Since `m + n <= 200`, an `O(m+n)` algorithm is trivial to fit within time limits.  
- The buffer of zeros at the end of `nums1` is a hint that we can write the merged result **in place** without allocating extra space.

### Key Observations

1. Both input arrays are already sorted in non‑decreasing order.  
2. We can merge by always placing the larger of the two current elements at the end of the destination array.  
3. Writing from the back of `nums1` prevents us from overwriting elements that we still need to compare.

### Edge Cases (based on the constraints)

| Edge case | Why it matters |
|-----------|----------------|
| `m = 0` (first array empty) | We must copy all elements from `nums2`. |
| `n = 0` (second array empty) | No work is needed; `nums1` already contains the correct result. |
| `m = n = 0` | Both arrays are empty; `nums1` remains unchanged. |
| One array contains all elements smaller than the other | The algorithm still works because we always compare the current ends. |
| Elements equal across arrays | The algorithm places the element from `nums2` when `nums1[i] <= nums2[j]`, preserving stability. |

## 3. Solution Development

### Core Intuition

The **key insight** is to start merging from the **end** of both arrays.  
By writing the largest remaining element into the last free position of `nums1`, we never overwrite an element that has not yet been examined.

### Algorithm Invariant

At the start of each iteration of the main loop:

- All positions **after** index `k` in `nums1` already contain the correct, merged elements.  
- `i` points to the last unmerged element of the original part of `nums1`.  
- `j` points to the last unmerged element of `nums2`.  
- `k` points to the last free position in `nums1` where the next largest element should be placed.

### Why It Works

Because both input arrays are sorted, the largest element among the two current candidates (`nums1[i]` and `nums2[j]`) must belong at the very end of the merged array.  
Placing it at `nums1[k]` and moving `k` leftwards preserves the sorted order for the suffix of the array.  
Repeating this process guarantees that the entire array is sorted once the loop terminates.

### Algorithm Strategy

1. Initialise three indices:  
   - `i = m-1` – last element of the original part of `nums1`.  
   - `j = n-1` – last element of `nums2`.  
   - `k = m+n-1` – last position of the merged array in `nums1`.  
2. While `j >= 0` (i.e., while there are still elements in `nums2`):  
   - If `i >= 0` **and** `nums1[i] > nums2[j]`, copy `nums1[i]` to `nums1[k]` and decrement `i`.  
   - Otherwise copy `nums2[j]` to `nums1[k]` and decrement `j`.  
   - Decrement `k` after each placement.  
3. When the loop ends, all elements of `nums2` have been merged; the remaining part of `nums1` (if any) is already in place.

## 4. Example Walkthrough (Example 1)

**Input:**  
`nums1 = [1,2,3,0,0,0]`, `m = 3`, `nums2 = [2,5,6]`, `n = 3`

| Step | i | j | k | Compare | Action | nums1 after action |
|------|---|---|---|---------|--------|--------------------|
| 0 | 2 | 2 | 5 | `nums1[2] = 3` vs `nums2[2] = 6` | `nums2[2]` is larger | `[1,2,3,0,0,6]` |
| 1 | 2 | 1 | 4 | `nums1[2] = 3` vs `nums2[1] = 5` | `nums2[1]` is larger | `[1,2,3,0,5,6]` |
| 2 | 2 | 0 | 3 | `nums1[2] = 3` vs `nums2[0] = 2` | `nums1[2]` is larger | `[1,2,3,3,5,6]` |
| 3 | 1 | 0 | 2 | `nums1[1] = 2` vs `nums2[0] = 2` | equal → copy from `nums2` | `[1,2,2,3,5,6]` |
| 4 | 1 | -1 | 1 | loop ends (j < 0) | – | `[1,2,2,3,5,6]` |

**Result:** `nums1` is now `[1,2,2,3,5,6]`.

## 5. Complexity Analysis

- **Time:** $O(m+n)$ – each element from `nums2` is processed once, and each element from the original part of `nums1` is moved at most once.  
- **Space:** $O(1)$ – only a few integer indices are used; no additional arrays are allocated.

## 6. Code Solution

```cpp
class Solution { public: void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) { 
    int i = m-1, j=n-1, k=m+n-1; // indices for end of nums1, nums2, and merged array
    while(j>=0){
        if( i >= 0 && nums1[i]>nums2[j]){
            nums1[k] = nums1[i]; // copy larger element from nums1
            i--; 
        } else{
            nums1[k] = nums2[j]; // copy from nums2 when nums1[i] is not larger
            j--; 
        } 
        k--; 
    } 
} };
```

## 7. Key Takeaways & Pattern Recognition

### Pattern Applies When

- Two sorted arrays must be merged **in place**.  
- The destination array has enough trailing space to hold the merged result.  
- Overwriting the source array would corrupt data if we started from the front.

### Reusable Pattern Structure

```cpp
int i = m-1;          // last valid element in first array
int j = n-1;          // last element in second array
int k = m+n-1;        // last position in destination array

while (j >= 0) {      // continue until all elements of second array are merged
    if (i >= 0 && first[i] > second[j]) {
        dest[k] = first[i];
        --i;
    } else {
        dest[k] = second[j];
        --j;
    }
    --k;
}
```

### Pattern Recognition

- **When to use:**  
  - Merging two sorted arrays where the destination has a buffer at the end.  
  - In‑place operations that would otherwise overwrite needed data.  
- **Typical problems:**  
  - LeetCode 88 – Merge Sorted Array  
  - LeetCode 23 – Merge k Sorted Lists (conceptually similar, but with a list of lists)  
  - LeetCode 80 – Remove Duplicates from Sorted Array II (two pointers, forward direction) – note the direction difference.  
- **Key invariant:**  
  - All positions **after** `k` are already correctly merged.  
- **Common pitfalls:**  
  - Forgetting to check `i >= 0` before accessing `nums1[i]`.  
  - Using `while (i >= 0 || j >= 0)` instead of `while (j >= 0)` – the loop must run until `nums2` is exhausted because any remaining `nums1` elements are already in place.

### Key Insights

1. **Reverse traversal** prevents overwriting elements that have not yet been compared.  
2. The loop condition `while (j >= 0)` guarantees that all elements from `nums2` are placed; any leftover elements in `nums1` are already in the correct position.  
3. The algorithm uses only **constant extra space**.

### Common Mistake

- **Neglecting the case when `i < 0`.**  
  If the first array is exhausted, the `else` branch must still copy from the second array. The provided code handles this correctly by checking `i >= 0` before comparing.

## 8. Final Thoughts

This reverse‑merge pattern is a classic example of **in‑place algorithm design**.  
By carefully choosing the traversal direction and maintaining a clear invariant, we can achieve optimal time and space complexity while keeping the code concise and robust.
