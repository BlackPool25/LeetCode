

# 15. 3Sum

## 0. Problem Metadata

- **Difficulty:** Hard  
- **Topics/Tags:** Array, Two Pointers, Sorting, Duplicate Handling  
- **Pattern Category:** **Two Pointers – Fixed Left, Two‑Sum**  
- **LeetCode Link:** <https://leetcode.com/problems/3sum/>

## 1. Problem Statement

> **Given an integer array `nums`, return all the triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, and `j != k`, and `nums[i] + nums[j] + nums[k] == 0`.**  
>  
> **Notice that the solution set must not contain duplicate triplets.**  
>  
> **Example 1:**  
> **Input:** `nums = [-1,0,1,2,-1,-4]`  
> **Output:** `[[-1,-1,2],[-1,0,1]]`  
> **Explanation:**  
> `nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0.`  
> `nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0.`  
> `nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0.`  
> The distinct triplets are `[-1,0,1]` and `[-1,-1,2]`.  
> The order of the output and the order of the triplets does not matter.  
>  
> **Example 2:**  
> **Input:** `nums = [0,1,1]`  
> **Output:** `[]`  
> **Explanation:** The only possible triplet does not sum up to 0.  
>  
> **Example 3:**  
> **Input:** `nums = [0,0,0]`  
> **Output:** `[[0,0,0]]`  
> **Explanation:** The only possible triplet sums up to 0.  
>  
> **Constraints:**  
> - `3 <= nums.length <= 3000`  
> - `-10^5 <= nums[i] <= 10^5`

## 2. Constraints & Key Observations

- **Constraints:**
  - `3 ≤ nums.length ≤ 3000`
  - `-10^5 ≤ nums[i] ≤ 10^5`
  - The array is not guaranteed to be sorted.
  - The array may contain negative, zero, and positive values.

- **What constraints tell us:**
  - `n ≤ 3000` allows an `O(n^2)` algorithm; `O(n^3)` would be too slow.
  - Sorting the array (`O(n log n)`) is acceptable and simplifies duplicate handling.

- **Key observations:**
  - After sorting, equal numbers become adjacent, making it easy to skip duplicates.
  - For a fixed left index `i`, the problem reduces to finding two numbers that sum to `-nums[i]` – a classic two‑sum on a sorted array.
  - Two pointers (`front` and `rear`) can scan the remaining part of the array in linear time.

- **Edge cases to handle:**
  - All elements are the same (e.g., `[0,0,0]`).
  - No valid triplet exists (e.g., `[0,1,1]`).
  - The array contains both negative and positive numbers.
  - Duplicate values that could form the same triplet (must be avoided).

## 3. Solution Development

### 3.1 Core Intuition

- **Aha! moment:**  
  Sorting the array lets us use a two‑pointer scan to find pairs that sum to a target, while also making duplicate detection trivial.

- **Algorithm invariant:**  
  For each chosen left index `i`, the subarray `nums[i+1 … n-1]` is sorted, and the two pointers `front` and `rear` always point to the smallest and largest remaining candidates, respectively.

- **Why this works:**  
  Because the array is sorted, if the sum of `nums[front] + nums[rear]` is too large, decreasing `rear` will reduce the sum; if it is too small, increasing `front` will increase the sum. This guarantees that all valid pairs are examined exactly once.

### 3.2 Algorithm Strategy

1. **Sort** the input array.  
2. Iterate `i` from `0` to `n-3` (inclusive).  
   - Skip `i` if it is a duplicate of the previous element to avoid duplicate triplets.  
3. For each `i`, set `front = i+1` and `rear = n-1`.  
   - Compute `diff = -nums[i]`.  
4. While `front < rear`:  
   - Compute `sum = nums[front] + nums[rear]`.  
   - If `sum == diff`, record the triplet, then move both pointers past any duplicates.  
   - If `sum > diff`, decrement `rear`.  
   - If `sum < diff`, increment `front`.  
5. Return the collected list of triplets.

## 4. Example Walkthrough

**Trace through Example 1: `nums = [-1,0,1,2,-1,-4]`**

1. **Initial state:**  
   - After sorting: `[-4, -1, -1, 0, 1, 2]`  
   - `result = []`

2. **Iteration `i = 0` (`nums[i] = -4`):**  
   - `front = 1`, `rear = 5`, `diff = 4`  
   - `sum = -1 + 2 = 1 < 4` → `front++` → `front = 2`  
   - `sum = -1 + 2 = 1 < 4` → `front++` → `front = 3`  
   - `sum = 0 + 2 = 2 < 4` → `front++` → `front = 4`  
   - `sum = 1 + 2 = 3 < 4` → `front++` → `front = 5` → loop ends.

3. **Iteration `i = 1` (`nums[i] = -1`):**  
   - `front = 2`, `rear = 5`, `diff = 1`  
   - `sum = -1 + 2 = 1 == diff` → add `[-1, -1, 2]` to `result`.  
   - Skip duplicates: `lastfront = -1`, `lastrear = 2` → `front` moves to `3`, `rear` stays `5`.  
   - Now `front = 3`, `rear = 5` → `sum = 0 + 2 = 2 > 1` → `rear--` → `rear = 4`  
   - `sum = 0 + 1 = 1 == diff` → add `[-1, 0, 1]`.  
   - Skip duplicates: `front` moves to `4`, `rear` moves to `3` → loop ends.

4. **Iteration `i = 2` (`nums[i] = -1`):**  
   - Skipped because `nums[2] == nums[1]`.

5. **Iteration `i = 3` (`nums[i] = 0`):**  
   - `front = 4`, `rear = 5`, `diff = 0`  
   - `sum = 1 + 2 = 3 > 0` → `rear--` → `rear = 4` → loop ends.

6. **Result:**  
   `result = [[-1,-1,2],[-1,0,1]]`

The algorithm found all unique triplets without revisiting duplicates.

## 5. Complexity Analysis

- Sorting: $O(n \log n)$  
- Outer loop: $O(n)$  
- Inner two‑pointer scan: each iteration moves `front` or `rear` at least once, so $O(n)$ per `i`.  
- Total time: $O(n^2)$  
- Extra space: $O(1)$ (excluding the output list).

## 6. Code Solution

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        vector<vector<int>> result;
        sort(nums.begin(), nums.end()); //sort the array
        for (int i = 0; i < nums.size() - 2; i++) {
            if (i > 0 && nums[i - 1] == nums[i]) continue;
            int front = i + 1;
            int rear = nums.size() - 1;
            int diff = 0 - nums[i];
            while (front < rear) {
                int sum = nums[front] + nums[rear];
                if (sum == diff) {
                    result.push_back({nums[i], nums[front], nums[rear]});
                    int lastfront = nums[front];
                    int lastrear = nums[rear];
                    while (front < rear && nums[front] == lastfront) front++;
                    while (front < rear && nums[rear] == lastrear) rear--;
                } else if (sum > diff) {
                    rear--;
                } else front++;
            }
        }
        return result;
    }
};
```

## 5. Pattern Recognition

### 5.1 Precise Pattern Name

**Two Pointers – Fixed Left, Two‑Sum**  
This captures the essence: a left index is fixed, and two pointers search for a complementary pair.

### 5.2 Reusable Template

```cpp
sort(nums.begin(), nums.end());          // 1. Sort the array
for (int left = 0; left < n - 2; ++left) {
    if (left > 0 && nums[left] == nums[left - 1]) continue; // skip left duplicates
    int front = left + 1;
    int rear  = n - 1;
    int target = -nums[left];
    while (front < rear) {
        int sum = nums[front] + nums[rear];
        if (sum == target) {
            // record solution
            // skip duplicates for both pointers
            int lastFront = nums[front];
            int lastRear  = nums[rear];
            while (front < rear && nums[front] == lastFront) ++front;
            while (front < rear && nums[rear]  == lastRear)  --rear;
        } else if (sum > target) {
            --rear;
        } else {
            ++front;
        }
    }
}
```

### 5.3 Specific Pattern Recognition

- **When to use this pattern?**  
  *Any problem that requires finding a triplet (or k‑tuple) that sums to a target in a sorted array.*  
- **Similar problems:**  
  - 2Sum (with duplicates)  
  - 4Sum  
  - 5Sum

  - “Three‑Way Partition” problems where a fixed pivot is combined with two pointers.

## 6. Key Takeaways

- **Sorting is the linchpin:** It turns a potentially cubic problem into a quadratic one and makes duplicate handling trivial.  
- **Two pointers on a sorted subarray** efficiently solve the two‑sum part for each fixed left index.  
- **Duplicate skipping** is essential:  
  - Skip duplicate left indices.  
  - After finding a valid pair, advance both pointers past any equal values.  
- **Time complexity** is dominated by the outer loop and inner two‑pointer scan: $O(n^2)$ after an $O(n \log n)$ sort.  
- **Space complexity** is $O(1)$ aside from the output list.
